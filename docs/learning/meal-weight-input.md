# 重量输入：一个解析方法，多个入口

## 为什么独立

`backend/app/agent/weight.py` 的 `parse_weight_grams(value)` 是无数据库、无模型、无网络的纯方法。它解析用户命令，而不是推断食物营养，因此归属 Agent 命令边界。规则版本为 `meal-weight-input.v1`。

支持纯数字默认克、g/克/公克、kg/千克/公斤、斤/市斤、两/市两。市斤、市两使用大陆标准 500g、50g。完整匹配后使用 Decimal 换算，再检查 `0 < grams <= 2000`。未知单位、体积、模糊份量、科学计数法和尾随文本拒绝，不截取数字猜测。

## 请求链路与恢复

H5 补充框与修正框保留整个重量字符串 → 公开 Agent input API → Service 从 checkpoint 判断等待问题 → 纯函数转换 → Graph 对指定项目重算 → 营养 Service 从目录计算和校验。

JSON 补充/修正和单问题纯文本回复复用同一方法。错误通过 `INVALID_WEIGHT` 返回安全的 422，在创建运行或改写 checkpoint 前拒绝。UI 保留原始填写内容并显示原因。其他无效恢复答案即使进入 Graph，也必须保留 waiting 状态，不能在 Service 提前改为 accepted 后误判为运行失败。

前端不重复维护换算表。它只拆出“菜名改为重量”中的完整重量部分，不能正则提取第一个数字：否则 `100kg` 会悄悄变成 `100g`。首次自然语言整餐理解仍属于 Provider 流程，本次不扩展为任意句子的确定性单位解析器。

## 测试方法

- 单测：单位别名、小数、空格、大小写、2000g 边界、超限、未知单位、非有限数及精度独立性；纯文本与 JSON 同值。
- PostgreSQL：公开接口拒绝多种非法重量后原快照不变；无效目标保持 waiting；0.1kg 恢复、3两修正，不重复解析模型。
- 组件：超限错误保留输入，改为0.1kg继续；修正1斤不得截断；文字失败不显示图片失败。
- 内置浏览器：真实“西兰花→100kg/100斤拒绝→0.1kg生成100克结果”，不确认保存测试餐食。

## 常见错误

不要用字符串 replace 去掉所有单位，不要用 float 做权威换算，不要让输入校验失败破坏业务会话，也不要仅测 Graph 的等待状态而忽略 Service 对状态的改写。
