# 2026-09-15 核心规划与质量门禁优化

## 完成范围

- 目标从 Agent 工具传入选菜服务；使用确定性、有上限的组合排序，优先满足营养校验，再比较目标偏差、口味和近期重复。
- 单餐替换保留其他餐次快照；“清淡”必须有受控标签支持，没有候选时有界结束。
- 忌口检查覆盖受控别名、菜名和已知配料。宏量比例先于可放宽目标校验，目标缺口不能掩盖比例不合格。
- 初始审核菜谱可用于首次规划；管理员已接管候选池后，即便全部停用，也不会重新启用初始候选。
- 混合检索的精确通道同时读取初始目录与后台合格发布目录；同名多个来源先确认，确认时重查资格。
- 刷新重放已保存计划时，不再把当前菜名误写成被替换的旧菜名。
- 图片替身评测明确标注证据范围，失败返回非零退出码。冻结检索评测在可回滚事务内隔离初始目录。
- 增加日常 CI：完整后端测试、两个前端类型检查/单测/构建、用户端静态检查，以及规划和后台配置/权限两个浏览器套件。

## 剩余边界与回滚

- 初始菜谱仍少，份量固定。本次虚构维持目标为 2,072–2,272 kcal，初始组合约 1,475 kcal，页面显示缺口；不能声称普遍达标。
- 复合菜未知配料、结构化过敏原尚未补齐；别名匹配不能证明完整过敏安全。
- 未实施真实图片/文本模型效果评测、原生 LangGraph StateGraph 迁移或生产应用部署。
- 两个前端仍有大构建分块警告；用户端有 React Hook Form 与编译器兼容性警告。
- 这轮没有数据库结构变更。回滚应恢复成套规划选择、工具版本及查询改动；已保存餐单是独立快照，不需重算或回填。
