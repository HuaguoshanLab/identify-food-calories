# Requirements: 多模态饮食健康智能 Agent

**Defined:** 2026-08-27
**Core Value:** 让用户通过图片或自然语言得到可追问、可校验、可追溯、能记住个人偏好的饮食分析与规划结果。

## v1 Requirements

### 身份与权限

- [x] **AUTH-01**：用户可以使用邮箱和密码注册，通过邮箱验证码激活账号，并完成登录与退出。
- [x] **AUTH-02**：密码使用强哈希保存，认证失败不泄露账号是否存在。
- [x] **AUTH-03**：短期 access token 与可撤销、可轮换的 HttpOnly refresh token 分离。
- [x] **AUTH-04**：用户可查看并撤销自己的登录会话。
- [x] **AUTH-05**：系统支持 `user`、`admin` 角色，后台 API 默认拒绝普通用户。
- [x] **AUTH-06**：注册验证与密码重置使用 6 位邮箱验证码和可替换 Mail Provider；验证码摘要保存、10 分钟过期、最多尝试 5 次、60 秒重发冷却、新码使旧码失效且成功后不可复用；本地使用 Mailpit。

### Agent 状态与工作流

- [x] **AGT-01**：LangGraph 主图按请求意图路由到餐食分析子图或饮食规划子图。
- [x] **AGT-02**：State 明确保存用户、线程、消息、图片引用、识别项、缺失字段、工具结果、校验问题、重试次数、下一动作和最终报告。
- [x] **AGT-03**：菜品模糊、识别失败或份量不足时，图通过 interrupt 暂停并向用户追问。
- [x] **AGT-04**：用户回复后，系统使用同一 `thread_id` 从持久化 Checkpoint 恢复，而不是重跑整条链路。
- [x] **AGT-05**：图设置最大循环、最大工具调用、超时和终止条件，不能无限重试。
- [x] **AGT-06**：每个节点、条件边和工具调用都可通过确定性测试替身验证。
- [x] **AGT-07**：Agent 运行记录包含图版本、模型版本、提示词版本、工具版本、状态与耗时。

### 多模态餐食分析

- [x] **VIS-01**：登录用户可拍照或上传餐食图片并看到隐私与留存说明。
- [x] **VIS-02**：服务端验证格式、大小、像素与真实解码，剥离元数据并拒绝危险图片。
- [x] **VIS-03**：Qwen-VL Provider 返回结构化多菜识别候选、置信度和份量线索。
- [x] **VIS-04**：识别结果归一化到受控菜品目录，目录外项目明确标记为未知。
- [x] **VIS-05**：模型或网络失败时有可操作的重试与降级路径，不产生重复费用。
- [x] **VIS-06**：原图只用于当前分析，完成或超时后删除；数据库不保存 base64 原图。

### 营养工具与结果校验

- [x] **NUT-01**：营养目录包含稳定 ID、别名、每 100g 营养、常见份量、来源、授权和版本。
- [x] **NUT-02**：`search_food_catalog` 工具只返回具备可计算资格的数据。
- [x] **NUT-03**：`calculate_nutrition` 根据菜品和克数确定性计算热量、蛋白质、脂肪和碳水。
- [x] **NUT-04**：`validate_nutrition_result` 检查负数、异常密度、总量不一致与越界份量。
- [x] **NUT-05**：校验异常时按明确规则重新核算、追问或终止，模型不能覆盖校验结果。
- [x] **NUT-06**：最终报告逐项展示菜名、克数、营养值、置信度和整餐汇总，并说明误差来源。
- [x] **NUT-07**：缺少授权或推导链的目录数据不能进入公开生产结果。

### 长期记忆与餐食记录

- [x] **MEM-01**：PostgreSQL 保存权威餐食记录、营养结果和用户确认，不由 Mem0 替代。
- [x] **MEM-02**：LangGraph PostgreSQL Checkpointer 保存线程级短期状态。
- [x] **MEM-03**：Mem0 只保存经白名单筛选的目标、忌口与稳定偏好，并绑定用户 ID。
- [x] **MEM-04**：长期记忆写入前可审计，读取时带来源和时间，不把推测当事实。
- [x] **MEM-05**：用户可以查看、修改和删除自己的长期记忆与餐食记录。
- [x] **MEM-06**：pgvector 支持营养知识与记忆的语义检索，并保留关系型过滤条件。

### 饮食规划子图

- [x] **PLN-01**：用户可提交身高、体重、活动水平、目标、忌口和口味偏好。
- [x] **PLN-02**：确定性工具计算每日热量与宏量营养目标，模型不自行编造公式结果。
- [x] **PLN-03**：规划子图检索受控菜谱，生成一日三餐候选。
- [x] **PLN-04**：校验工具检查总热量、宏量营养比例、忌口与重复度，不合格时有界重排。
- [x] **PLN-05**：用户可以通过自然语言要求替换、变清淡或排除食物，图在保留约束后重新规划。
- [x] **PLN-06**：所有建议明确标注为普通饮食参考，不提供疾病治疗或医疗诊断。

### 用户端与后台管理

- [x] **UI-01**：React 应用包含登录注册、Agent 对话、图片上传、追问恢复、结果报告和饮食规划页面。
- [x] **UI-02**：用户可查看今日/本周摄入、历史餐食、营养趋势和周复盘。
- [x] **UI-03**：流式状态清楚展示感知、等待补充、工具计算、校验和完成，但不暴露模型思维链。
- [x] **ADM-01**：`/admin` 仅管理员可访问，前后端同时执行 RBAC。
- [x] **ADM-02**：管理员可管理菜品、别名、标准营养、来源、授权状态和数据版本。
- [x] **ADM-03**：管理员可查看 Agent 运行、失败节点、工具调用、费用与延迟，但看不到不必要的敏感原文或原图。
- [x] **ADM-04**：管理员可启停模型 Provider、配置模型版本和费用上限，密钥不可在页面回显。
- [x] **ADM-05**：所有后台变更保存操作者、时间、前后值和原因。

### 工程、教学与质量

- [x] **ARC-01**：仓库保持独立 `frontend/` 与 `backend/`，后端为模块化单体。
- [x] **ARC-02**：FastAPI 使用 API → Service/Use Case → Repository → Model 分层，Agent 编排层只能通过工具调用领域服务。
- [x] **ARC-03**：SQLAlchemy Model、Pydantic Schema、LangGraph State 与 Provider DTO 分离。
- [x] **ARC-04**：PostgreSQL、pgvector 与所需本地依赖通过 Docker Compose 启动，迁移显式执行。
- [x] **ARC-05**：前后端使用版本化 OpenAPI 契约；流式 Agent 事件使用 SSE。
- [x] **ARC-06**：模型 Provider 可替换且具备 fake 实现，测试不依赖真实付费 API。
- [x] **ARC-07**：仓库根目录、`frontend/` 与 `backend/` 各自维护 `README.md` 和 `AGENTS.md`；新增任何目录时必须在同次提交创建该目录的 `README.md`，写明职责、允许依赖和文件索引。
- [x] **ARC-08**：管理后台使用独立的 `admin-frontend/` React 项目，与 `frontend/`、`backend/` 同级并独立构建部署；后台与用户端共用 FastAPI，但后台权限始终由 `/api/v1/admin/*` 的后端 RBAC 强制执行。
- [x] **EDU-01**：每个后端阶段或功能变更后，按功能更新 `docs/learning/feature-*.md` 及总目录，不再新增 Phase 教程；每篇包含功能概述、核心能力、业务背景、简单执行流程、真实源码位置与精简主逻辑、单独语法解释、测试方法和常见错误，使用通俗中文并侧重 AI 与后端；旧资料仅归档于 `docs/after/`。
- [x] **EDU-02**：README 包含架构图、LangGraph 状态图、关键时序图、启动与调试命令。
- [x] **EDU-03**：关键模块配套面试深挖题和可验证答案线索。
- [x] **QLT-01**：餐食识别、归一化、估重和营养区间在冻结评测集上达到预先定义门槛。
- [x] **QLT-02**：Agent 路由、interrupt/resume、循环终止和工具选择具有状态图测试。
- [ ] **QLT-03**：认证、越权、危险图片、提示注入、费用上限、记忆隔离和删除链通过安全测试。
- [ ] **QLT-04**：CI 运行 lint、类型检查、单元、真实 PostgreSQL 集成、API 合约和 Playwright E2E。
- [ ] **QLT-05**：Docker 本地环境可一键启动演示，敏感密钥全部来自未提交环境变量。

## Explicit Non-Requirements

- 大模型直接生成权威营养数值。
- 万相图像生成模型承担视觉识别。
- 医疗诊断、药物或疾病治疗建议。
- 微服务、Kafka、Kubernetes 或无限制自治循环。
- 将模型思维链展示给用户或管理员。
