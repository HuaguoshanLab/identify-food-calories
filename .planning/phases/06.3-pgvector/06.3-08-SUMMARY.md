**Catalog publication now atomically enqueues normalized canonical/alias work for active vector spaces, while administrators receive safe aggregate lifecycle status and replay-safe finite-budget retries.**

## Accomplishments

- Publication writes a content-bound search version, unique normalized canonical/controlled-alias names and one pending job per active target vector space in its existing transaction.
- Added a safe aggregate response (`pending`, `processing`, `partial_failure`, `failed`, `ready`) with job IDs, vector-space IDs, attempts, error codes and timestamps only.
- Added publication-scoped advisory locking and request-hash-backed audit replay for concurrent retry commands; retries leave exhausted jobs untouched and do not reset attempt budgets.
- Added real PostgreSQL tests for publication replay, partial failure, concurrent retry and no duplicate job creation.

## Decisions Made

- The existing append-only `AdminAuditEvent` is the retry command record: its unique command key, request hash (`related_version`) and scalar before/after counts make replay deterministic without an incompatible schema change.
- An active vector-space pointer is the only target at publication time. If no pointer exists, exact/text publication remains valid and later Plan 21 backfill is responsible for a newly created vector space.
