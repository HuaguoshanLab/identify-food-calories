# Phase 06.3 Plan 10: Finite Catalog Embedding Worker Summary

实现了受控、可恢复的 catalog embedding worker：它只消费 immutable vector-space build manifest 中的 job，在 Provider I/O 前后重读 PostgreSQL 权威资格，并在精确覆盖整个冻结 manifest 后写入独立 completion evidence。

## Delivered

- `CatalogEmbeddingWorker` 每次最多 lease 一个到期 job；lease 使用 `FOR UPDATE SKIP LOCKED`、有限 attempts、指数退避和安全失败码。
- Provider 只接收一个 `normalized_name` document；没有用户输入、餐食、身份或健康信息进入 embedding 调用。
- 失格、内容版本变更、manifest 不匹配或 lease 失效均安全终止，不写入向量；写回通过唯一 business key 锁定 upsert，避免双重计费和重复向量。
- build reconciliation 锁定 build，要求 ready embedding 的 `(publication_id, name_id)` 集合与原始 manifest 完全一致，才创建单独 completion evidence；worker 不修改 manifest，也不切换 active vector-space pointer。
- 真实 PostgreSQL 合同覆盖完整 manifest 执行、completion evidence 和未激活保证。
