# Phase 06.3 Plan 17: Controlled Activation Summary

**只有数据库确认的管理员、已验证的 release 哈希、指定 build manifest 及独立 completion evidence 同时成立时，才会原子切换 active vector-space pointer。**

## Accomplishments

- 新增最小 `activate.py` CLI：只接收 actor、space、build、原因、幂等键与 release 路径；身份与 PASS 结论均不被 CLI 信任。
- `AdminService` 重新读取 PostgreSQL ADMIN 角色，复算 release、数据集、评测器和检索策略文件 hash，验证冻结的 embedding/model/dimension/adapter/retrieval identity。
- 精确校验 `build_id` 所属空间、manifest hash/count、独立 completion hash/count、每项 completed job 与 ready embedding；任一差异均不改变 pointer。
- approval、审计事件与 active pointer 在同一个 advisory-lock/row-lock 事务中写入；同幂等键的相同请求返回原 approval，参数变更拒绝。
- 修复可复用 vector space 的跨计划缺口：后续 immutable manifest 可以从既有 completed job/ready embedding 生成自己的 completion evidence；worker 空闲时只作本地 reconciliation，不重复 Provider 调用，也不激活空间。

## Deviations from Plan

### Approved Cross-Plan Correction

1. **Explicit immutable build binding and reusable-space reconciliation**
   - **Found during:** Task 1 real PostgreSQL validation.
   - **Issue:** A vector-space identity may own more than one immutable manifest. Selecting a space alone would force activation to guess a snapshot; a later manifest reusing completed jobs could also lack its own completion evidence.
   - **Fix:** Activation now requires `build_id`; repository/worker reconciliation creates evidence per exact manifest from already-ready rows without Provider I/O or pointer mutation.
   - **Authorization:** Parent executor approved Rule 4 minimal cross-plan fix.
   - **Files modified:** admin service/repository/port, nutrition worker/search repository and integration contracts.

2. **Idle scoped-worker reconciliation**
   - **Found during:** Main-branch persistent PostgreSQL revalidation.
   - **Issue:** A scoped worker with only already-completed jobs returned `idle`; completion evidence could remain absent after an interrupted reconciliation.
   - **Fix:** On an idle scoped run, reconcile every missing completion against exact manifest jobs and ready embeddings; partial, failed or mismatched rows still write nothing and no Provider call occurs.
   - **Verification:** Real PostgreSQL regression simulates deletion of only the derived completion evidence, then proves an idle worker recreates it before controlled activation.
