## 1. System Classification

**System Type:** Hybrid

**Description:**
这是消费级饮食健康助手中的受控菜品编码与检索能力：把用户输入的中文菜名映射到具备来源、营养字段、资格状态和目录版本的权威条目。系统先执行唯一 canonical name/alias 精确匹配；没有唯一精确结果时，以模糊文本和语义检索召回最多 3 个候选并要求用户确认。好的结果不是“猜中最像的菜”，而是精确匹配可直接采用、歧义表达得到少量可解释候选、无法可靠匹配时明确无结果，且最终营养计算只读取用户确认后的当前合格目录条目。

**Critical Failure Modes:**
1. 将模糊文本或向量近邻自动当作用户吃的菜，使错误菜品进入后续确定性营养计算或餐食记录。
2. 召回已撤销、已失格、旧版本、来源或关键营养字段不完整的目录条目，绕过权威目录资格边界。
3. 丢失加工、烹调、形态或地域描述，把营养组成不同的食物错误合并，例如把“米饭”与“蛋炒饭”视为同一精确食物。
4. 为凑满 Top 3 返回仅共享单一食材的无关菜品，或在索引/Embedding 故障时扩大自动选择权限。
5. 将真实用户餐食、身份、身体/健康信息、图片或查询向量写入 Embedding Provider、Langfuse 或持久化追踪数据。

## 1b. Domain Context

> Researched by `gsd-domain-researcher`. Grounds the evaluation strategy in domain expert knowledge.

**Industry Vertical:** 消费级数字营养与饮食自我管理（非医疗诊断或治疗）

**User Population:** 使用中文自然语言或餐食识别结果记录饮食、查看营养摄入或生成普通饮食计划的消费者；营养目录管理员负责发布和维护受控条目。

**Stakes Level:** High

**Output Consequence:** 检索结果决定后续使用哪个目录条目进行热量和宏量营养的确定性计算，并可能进入餐食记录、趋势统计和饮食规划。错误匹配会产生形式上精确、实质上基于错误食物的结果；本系统只提供普通饮食参考，不把该输出用于疾病诊断、治疗或药物决策。

### What Domain Experts Evaluate Against

**Dimension: 菜品身份与描述一致性**  
**Good (domain expert would accept):** 只有名称及影响营养值的关键描述足以唯一识别同一条目时才视为精确；加工/烹调状态、食物形态、主要组成或地域含义不明确时返回可区分候选并追问。  
**Bad (domain expert would flag):** 因字符串或向量相近就把“米饭”匹配为“蛋炒饭”，或忽略鲜/干、煮/炸、部位、品牌/配方等会改变营养组成的描述。  
**Stakes:** Critical  
**Source:** FAO/INFOODS Food Matching Guidelines：食品名称和描述应支持无歧义识别，加工与烹调状态会显著改变营养摄入估计。

**Dimension: 不确定时由用户确认**  
**Good (domain expert would accept):** 唯一受控精确匹配可以直接采用；任何仅由模糊或语义通道得到的结果，即使只有一个且排名很高，也标为候选并要求确认；没有可靠候选就明确无结果。  
**Bad (domain expert would flag):** 将 Top 1 或相似度阈值等同于身份确定性，自动写入餐食记录，或用低质量候选凑满列表。  
**Stakes:** Critical  
**Source:** FAO/INFOODS 将 exact、similar、poor match 分级并要求记录匹配质量；本阶段产品安全合同进一步规定所有非精确匹配必须确认。

**Dimension: 目录资格、来源与版本可追溯**  
**Good (domain expert would accept):** 每个候选都能追溯到当前合格目录的稳定 ID、发布版本、数据来源和匹配类型；确认后按 `food_id + catalog_version` 重新读取权威条目。  
**Bad (domain expert would flag):** 返回已撤销、失格、旧版本或缺少计算字段的条目，或只保留显示名而无法复现使用了哪版营养数据。  
**Stakes:** Critical  
**Source:** FAO/INFOODS 要求食品匹配记录来源、数据库 release/edition 和具体 item number，以判断匹配及营养摄入估计质量。

**Dimension: 中文地域名称与相近菜式覆盖**  
**Good (domain expert would accept):** 常见同义名、地域修饰和相近做法能把预期受控条目放入 Top 3，并以“名称相近”“地域/做法变体”“同类食物”等标签解释关系；只返回达到可靠边界的候选。  
**Bad (domain expert would flag):** 对常见地方叫法稳定漏检，或仅因共享牛肉、鸡蛋、土豆等单一食材就返回不同菜品。  
**Stakes:** High  
**Source:** FAO/INFOODS 指出食物名称会因国家和地区变化，食物描述应覆盖当地名称、来源和制备形态；项目锁定冻结用例用于中文场景校准。

**Dimension: 营养后果的保守性**  
**Good (domain expert would accept):** 检索层只识别受控条目，不生成、平均或改写营养值；烹调方式、含水量、含脂量或配方可能造成实质差异时保留歧义并请求确认。  
**Bad (domain expert would flag):** 用“同类食物”的数值冒充用户所食菜品，或让模型/检索分数成为营养数值与权威条目的来源。  
**Stakes:** High  
**Source:** FAO/INFOODS 说明忽略制备状态、含水量和脂肪差异会导致营养摄入高估或低估；自动化饮食评估研究也报告错误食品编码可造成显著能量估计误差。

### Known Failure Modes in This Domain

1. **名称相同但食物不同：** 地域叫法、复合菜简称或品牌/配方差异被压成一个 canonical name，导致错误营养条目被采用。
2. **加工状态被抹平：** 鲜/干、生/熟、蒸/炸、原味/加油等描述在归一化或 embedding 中丢失，造成能量、脂肪和含水量明显不同的条目互相替代。
3. **近邻污染候选：** 语义搜索按共同食材聚类，把“含鸡蛋”或“含牛肉”的不同菜品当成可替代关系；Top 3 表面相关，实际无法支持营养匹配。
4. **目录时态错误：** 异步向量索引仍含旧版本或撤销条目；若查询不同时执行当前资格过滤，历史数据会泄露到新候选。
5. **评测选择偏差：** 只保留成功实验、用精确同名 fixture 绕过非精确召回，或未覆盖无结果和降级场景，会虚高 Top 3 召回并掩盖自动误选风险。

### Regulatory / Compliance Context

本阶段输出属于普通饮食记录和营养参考，不提供医疗诊断、治疗或药物建议，因此不能宣称临床有效性，也不能把检索结果升级为疾病干预结论；若未来进入医疗用途，必须另行进行产品定位和适用监管评估。

在中国部署时，单个去关联的菜名通常不必然构成医疗健康信息，但餐食、身体指标或健康目标一旦与可识别用户、账号或长期画像关联，就可能成为个人信息，其中医疗健康信息属于《中华人民共和国个人信息保护法》第二十八条规定的敏感个人信息。处理此类信息需要特定目的、充分必要性和严格保护措施；涉及敏感个人信息时还需遵守单独同意和影响告知等要求。因此，本阶段坚持数据最小化：Embedding 仅接收规范化单项菜名；查询文本/向量不持久化；Langfuse 仅接收合成或去标识化冻结用例及 allowlist metadata，不接收用户身份、真实餐食、身体/健康数据或图片。若 Provider 或观测服务涉及向境外提供个人信息，还需在启用前单独评估《个人信息保护法》第三章的跨境规则；当前设计通过禁止发送相关个人信息避免把该风险引入本阶段。

## 2. Framework Decision

**Selected Framework:** LangGraph

**Version:** 1.2.11

**Rationale:**

| Framework | Ruled Out Because |
|-----------|------------------|

**Vendor Lock-In Accepted:** Partial — Agent 编排保持模型无关；Embedding 通过可替换 Provider 接口隔离，生产默认 DashScope，测试使用 Fake Provider。

### Entry Point Pattern
```python
from collections.abc import Awaitable, Callable
from typing import Literal, NotRequired, TypedDict

from langgraph.graph import END, START, StateGraph


class SearchState(TypedDict):
    query: str
    action: NotRequired[Literal["PASS", "ASK"]]
    selected_food_id: NotRequired[str | None]
    candidate_ids: NotRequired[list[str]]


def build_search_graph(
    search_food: Callable[[str], Awaitable[dict[str, object]]],
):
    """最小示例；生产代码注入 Nutrition Tool，而不是 Repository 或 Provider。"""

    async def resolve_food(state: SearchState) -> dict[str, object]:
        result = await search_food(state["query"])
        return {
            "action": result["action"],
            "selected_food_id": result.get("selected_food_id"),
            "candidate_ids": result.get("candidate_ids", []),
        }

    builder = StateGraph(SearchState)
    builder.add_node("resolve_food", resolve_food)
    builder.add_edge(START, "resolve_food")
    builder.add_edge("resolve_food", END)
    return builder.compile()


# 使用时：result = await graph.ainvoke({"query": "西红柿炒鸡蛋"})
# 预期：非精确候选只能得到 ASK；唯一精确匹配才允许 PASS。
```

### Key Abstractions
| Concept | What It Is | When You Use It |
|---------|-----------|-----------------|
| `StateGraph` / compiled graph | LangGraph 的显式状态机；节点可为同步或异步函数 | 保留现有主图和餐食分析、饮食规划子图；本阶段不另建一套 RAG Agent |
| Nutrition Tool port | 图与确定性应用服务之间的窄接口 | 两个 Agent 流程调用同一混合检索语义，图不接触 SQLAlchemy、向量或供应商 SDK |
| Pydantic DTO | Provider DTO、内部候选 DTO、Graph State 分离的运行时合同 | 校验输入长度、向量维度/有限值、候选上限及 `PASS/ASK` 不变量 |
| PostgreSQL qualified query | 将资格、当前版本、publication eligibility 与候选召回放在同一权威查询边界 | 精确、`pg_trgm` 和 pgvector 三条通道都必须在物化前排除失格/撤销/旧版本记录 |
| Checkpointer / `thread_id` | LangGraph 在 super-step 边界保存状态并按线程恢复 | 保存确认等待状态和候选安全投影；不得保存查询向量、内部相似度或 Provider 原文 |

### Common Pitfalls
1. **把“第一名”当成可信答案。** pgvector 最近邻只表达向量距离，不证明是同一道菜；本阶段所有非精确命中，即使只有一个候选，也必须 `ASK`。
2. **先做 ANN 再在 Python 过滤资格。** HNSW/IVFFlat 的 Top K 可能全是失格或旧版本记录，过滤后既漏召回又可能泄露；资格和向量空间版本条件必须进入 SQL 候选查询，并在确认后按 `food_id + catalog_version` 权威重读。
3. **混用距离算子、索引算子类或向量维度。** `cosine_distance()` 必须对应 `vector_cosine_ops`；模型/维度升级必须并行建新空间后原子切换，不能把不同空间放进同一次排序。
4. **把同步数据库/HTTP 调用塞进 async 节点。** 这会阻塞 FastAPI 事件循环；Embedding 使用 `httpx.AsyncClient`，现有同步 SQLAlchemy 查询若暂不迁移 `AsyncSession`，必须在由 adapter 创建和关闭 Session 的受控线程中执行。
5. **在 checkpoint 中保存搜索实现细节。** LangGraph 会持久化每个 super-step；保存查询向量、完整候选对象或供应商响应会扩大敏感面并让恢复依赖过期索引。只保存 ID、目录版本、关系标签和业务动作。
6. **在 `interrupt()` 前执行非幂等副作用。** LangGraph 恢复时会从节点开头重放；索引任务入队、实验发布等副作用必须放在幂等 service/outbox 中，不能依赖节点“只执行一次”。

## 4. Implementation Guidance

**Model Configuration:**

- 生产默认：DashScope `text-embedding-v4`，`dimension=1024`，`output_type="dense"`。目录名称使用 `text_type="document"`，在线查询使用 `text_type="query"`。
- 只输入 `normalize_food_name()` 后的单个菜名，应用层继续限制为 1–200 字符；不发送完整餐食、份量、用户/健康数据或历史对话。
- Embedding 没有 `temperature` 或生成式 `max_tokens`。应显式限制批量：在线查询每次 1 条，目录构建每批最多 10 条（供应商 v4 上限）；响应必须校验数量、1024 维、全为有限浮点数。
- 固定 `embedding_model=text-embedding-v4`、`embedding_dimension=1024`、Provider adapter version 与价格快照版本。模型或维度变化视为新向量空间，不得原地混写。
- 测试只注入 Fake Provider；生产必须显式选择 DashScope 并校验 API key、HTTPS endpoint、region/deployment scope、超时和单次/周期成本上限，配置缺失时 fail closed。在线语义调用失败则安全降级到精确/模糊文本，不扩大 `PASS` 权限。

**Core Pattern:**

采用“应用服务编排、Repository 执行 SQL、Provider 只生成向量、Graph 只调用 Tool”的四层模式。唯一精确查询先短路，只有无唯一精确结果时才调用 Embedding；文本与向量候选先按当前资格过滤，再由版本化的确定性融合器去重和排序。

```python
from __future__ import annotations

import asyncio
from dataclasses import dataclass, replace
from typing import Protocol


@dataclass(frozen=True, slots=True)
class Candidate:
    food_id: str
    catalog_version: str
    relation_layer: int       # 0 名称变体，1 地域/做法，2 同类成品菜
    text_rank: int | None
    vector_rank: int | None


class EmbeddingProvider(Protocol):
    async def embed_query(self, normalized_name: str) -> tuple[float, ...]: ...


class EmbeddingUnavailableError(RuntimeError):
    """Provider adapter 已移除供应商响应内容的安全失败。"""


class FoodSearchRepository(Protocol):
    def find_unique_exact(self, normalized_name: str) -> Candidate | None: ...
    def fuzzy_candidates(self, normalized_name: str, *, limit: int) -> list[Candidate]: ...
    def vector_candidates(
        self, vector: tuple[float, ...], *, vector_space: str, limit: int
    ) -> list[Candidate]: ...


class HybridFoodSearchService:
    def __init__(self, repository: FoodSearchRepository, embeddings: EmbeddingProvider) -> None:
        self._repository = repository
        self._embeddings = embeddings

    async def search(self, normalized_name: str) -> tuple[str, tuple[Candidate, ...]]:
        exact = self._repository.find_unique_exact(normalized_name)
        if exact is not None:
            return "PASS", (exact,)  # 只有这个分支可以自动选择

        text_hits = self._repository.fuzzy_candidates(normalized_name, limit=20)
        try:
            vector = await asyncio.wait_for(
                self._embeddings.embed_query(normalized_name), timeout=1.5
            )
            vector_hits = self._repository.vector_candidates(
                vector, vector_space="dashscope-text-embedding-v4-1024.v1", limit=20
            )
        except (TimeoutError, EmbeddingUnavailableError):
            vector_hits = []  # 降级后仍然只能 ASK

        # 实际融合器按 relation_layer 优先，在层内使用版本化 RRF/分数，
        # 最终以 catalog_version、food_id 作稳定 tie-breaker，并由冻结集校准阈值。
        merged = deterministic_merge(text_hits, vector_hits)[:3]
        return "ASK", tuple(merged)


def deterministic_merge(
    text_hits: list[Candidate], vector_hits: list[Candidate]
) -> list[Candidate]:
    by_id: dict[tuple[str, str], Candidate] = {}
    for hit in [*text_hits, *vector_hits]:
        key = (hit.food_id, hit.catalog_version)
        previous = by_id.get(key)
        if previous is None:
            by_id[key] = hit
        else:
            # 同一菜品命中两个通道时合并 rank，而不是重复返回。
            by_id[key] = replace(
                previous,
                relation_layer=min(previous.relation_layer, hit.relation_layer),
                text_rank=previous.text_rank or hit.text_rank,
                vector_rank=previous.vector_rank or hit.vector_rank,
            )

    def rank_key(hit: Candidate) -> tuple[object, ...]:
        # RRF 常数只是示例；最终值必须写入 retrieval_version 并由冻结集校准。
        rrf = sum(
            1.0 / (60 + rank)
            for rank in (hit.text_rank, hit.vector_rank)
            if rank is not None
        )
        return (
            hit.relation_layer,
            -rrf,
            hit.text_rank if hit.text_rank is not None else 10_000,
            hit.vector_rank if hit.vector_rank is not None else 10_000,
            hit.catalog_version,
            hit.food_id,
        )

    return sorted(
        by_id.values(),
        key=rank_key,
    )
```

上例只展示边界和失败语义。真正的关系层判定、`pg_trgm` 阈值、候选池和层内融合公式必须拥有 `retrieval_version`，由冻结数据集校准；不得把示例常量当作已验收参数。

**Tool Use:**

- PostgreSQL 启用 `vector` 与 `pg_trgm` 扩展；使用 Alembic 建真实维度 `VECTOR(1024)`、模型/维度/索引版本字段和部分 HNSW cosine 索引。SQLAlchemy 使用 `pgvector.sqlalchemy.VECTOR` 与 `.cosine_distance()`，索引 operator class 必须为 `vector_cosine_ops`。
- 精确通道独立查询 canonical name 与 controlled alias；只有恰好一个当前合格结果时短路 `PASS`。若精确结果不唯一，继续混合召回并 `ASK`。
- 模糊通道建议使用 `pg_trgm` 的 `similarity`/trigram 索引；阈值、候选池大小和关系层分类都纳入 `retrieval_version`，以冻结集选择，禁止凭经验硬宣称质量达标。
- DashScope adapter 只接收最小化 DTO，并返回严格 Pydantic DTO；HTTP 重试只覆盖明确可重试且尚未形成不确定计费/副作用的失败。在线查询总时限到达后立即文本降级；异步建索引使用有限重试、任务租约和人工重试。
- Langfuse 只由评测 CLI 在 `--publish-langfuse` 下使用；先通过 allowlist 检查，再镜像 dataset hash、代码/检索/embedding 版本、候选安全投影、耗时和确定性 score。在线服务、普通测试及 CI PASS/FAIL 不依赖 Langfuse。

**State Management:**

- PostgreSQL 业务表保存权威菜品、当前 publication pointer 和资格事件；目录 embedding、索引状态和任务只是可重建派生状态。
- LangGraph checkpoint 只保存业务恢复所需的安全投影：`food_id`、`catalog_version`、显示名称、关系标签、`PASS/ASK`、检索版本。不得保存查询向量、相似度、供应商响应或密钥。
- 用户确认后必须按 checkpoint 中的 `food_id + catalog_version` 重新读取权威目录并再次执行资格检查；索引命中本身不是授权。
- 发布新版本时先原子切换权威版本，使精确/文本立即可见，再异步生成该版本向量；新向量空间完成并通过冻结评测后原子切换 active index pointer。失格/撤销通过实时 SQL 谓词立即生效，物理清理可延后。
- 当前 Agent run 内可以按规范化菜名复用一次查询向量；run 结束即释放，不写 checkpoint、数据库、Langfuse 或日志。

**Context Window Strategy:**

这不是文档 RAG，检索层不应接收对话窗口。上游解析只传一个规范化菜名（应用合同最多 200 字符）给 Embedding Provider；目录侧也只嵌入受控 canonical name/alias。候选返回最多 3 项安全摘要，内部候选池和向量不进入模型上下文。若 Agent 对话需要压缩，保留已确认的 `food_id + catalog_version`、待确认问题和用户显式修正，丢弃旧候选分数及原始 Provider 内容；营养数值始终重新由确定性工具读取/计算。

## 4b. AI Systems Best Practices

> Written by `gsd-ai-researcher`. Cross-cutting patterns every developer building AI systems needs — independent of framework choice.

### Structured Outputs with Pydantic

```python
from typing import Literal
from uuid import UUID

from pydantic import BaseModel, ConfigDict, Field, model_validator


class FoodCandidateDTO(BaseModel):
    model_config = ConfigDict(extra="forbid", frozen=True)

    food_id: UUID
    catalog_version: str = Field(min_length=1, max_length=80)
    canonical_name: str = Field(min_length=1, max_length=200)
    relation: Literal["名称相近", "地域/做法变体", "同类食物"]


class HybridFoodSearchResultDTO(BaseModel):
    model_config = ConfigDict(extra="forbid", frozen=True)

    action: Literal["PASS", "ASK"]
    match_channel: Literal["exact", "hybrid", "text_fallback", "none"]
    selected_food_id: UUID | None = None
    candidates: tuple[FoodCandidateDTO, ...] = Field(default=(), max_length=3)
    retrieval_version: str = Field(min_length=1, max_length=80)

    @model_validator(mode="after")
    def enforce_resolution_contract(self) -> "HybridFoodSearchResultDTO":
        if self.action == "PASS":
            if self.match_channel != "exact" or self.selected_food_id is None:
                raise ValueError("PASS requires one unique exact match")
            if self.candidates:
                raise ValueError("PASS must not expose competing candidates")
        elif self.selected_food_id is not None:
            raise ValueError("non-exact retrieval must never auto-select")
        return self
```

本阶段的搜索结果不是 LLM 生成内容，因此不要为它套用 LangChain `.with_structured_output()`：Repository/Service 直接构造上述 DTO，Pydantic 校验失败就是代码或数据合同错误，应 fail closed 并告警，不能让模型“修复”权威结果。若上游 DeepSeek/Qwen 负责从自然语言或图片提取菜名，继续沿用项目现有 Provider DTO + JSON Schema/Pydantic 校验：最多一次针对 schema/safety 的纠正重试；记录 `error_code`、model alias、prompt/schema version、attempt、token/cost 和 latency，不记录输入、输出或完整校验正文。第二次仍失败时返回安全追问/停止，不得猜测菜品。

Embedding 响应也必须是独立 Pydantic DTO：要求返回项数与请求相等、每项正好 1024 维、所有值为有限数、usage 非负。维度或非有限值属于永久合同失败，不重试并触发文本降级；429/5xx 等瞬态失败最多一次受预算约束的重试。

### Async-First Design

LangGraph 支持 async 节点和 `graph.ainvoke()`/`graph.astream()`。搜索 Tool port 应升级为 async：节点 `await tools.search_food_catalog(...)`，DashScope adapter 使用 `httpx.AsyncClient`，超时和取消必须向下传播。现有同步 SQLAlchemy adapter 若本阶段不迁移 `AsyncSession`，应在基础设施 adapter 的受控 worker thread 内创建、使用并关闭 Session；禁止跨线程传递同一个 Session。

最常见错误是在 FastAPI/LangGraph 已运行的事件循环中调用 `asyncio.run()`，这会直接报错或破坏取消语义；从入口到 Provider 一路 `await`。面向用户的过程更新可用 `astream(stream_mode="updates")`，但候选决策必须等待精确、文本、向量、资格过滤和 Pydantic 校验完整结束后一次性提交；不能流式展示尚未过滤的中间候选。

### Prompt Engineering Discipline

Embedding 路径原则上没有生成式 prompt。固定任务说明（若启用 DashScope `instruct`）属于版本化系统配置，规范化菜名属于用户数据，两者必须分字段发送，不能字符串拼接后允许用户覆盖说明；`instruct` 只用于 `text_type="query"` 并会计入 Token，应先用冻结集证明收益。

上游菜名抽取继续保持 system/instructions 与 user content 分离，只要求输出菜名和结构化字段，严禁让模型输出营养数值或选择 catalog ID。五个锁定例子属于离线评测集，不应全部塞进每次在线 prompt；只有稳定、极少量格式示例可内联，失败案例扩展应通过版本化评测而不是动态检索真实用户数据。所有生成模型显式设置输出上限；沿用当前解析上限（例如 `max_output_tokens=800`），生产不得留空为无界生成。

### Context Window Management

Embedding 输入在进入 Provider 前按 Pydantic 限为单项、最多 200 字符，远低于 `text-embedding-v4` 的 8,192 Token 单条上限；禁止把完整对话、食谱或营养记录拼入输入。混合搜索只对每通道有限候选池排序，并在 Tool 边界截断为 0–3 项。

LangGraph 的会话压缩只需要保留已经确认的稳定标识、目录版本、待确认项及显式修正；早期自然语言、旧候选和检索分数可以摘要或丢弃。恢复后按稳定标识重读 PostgreSQL，而不是相信 checkpoint 中的旧候选快照。没有文档 chunk，因此不引入 RAG reranker 或上下文拼接层。

### Cost and Latency Budget

以阿里云北京区 2026-09-10 公示的 `text-embedding-v4` 文本输入 **¥0.5/百万 Token** 为价格快照。若一个规范化菜名平均按 12 Token 估算，10 万次非精确查询/日约为 120 万 Token，即约 **¥0.60/日**；1 万个目录名称全量重建约 12 万 Token，即约 **¥0.06/次**。这是容量预算示例，不是已测生产用量；实现必须用供应商返回 usage 和版本化价格快照计算真实成本。

初始 SLO 建议：唯一精确 p95 ≤ 50 ms；文本降级 p95 ≤ 150 ms；含在线 embedding 的非精确搜索 p95 ≤ 1.5 s，Provider 硬超时 1.5 s，整个 Tool 调用仍受图级超时/成本上限约束。具体值必须用本地 PostgreSQL 和真实区域压测校准。

缓存顺序：唯一精确结果直接短路，不产生模型费用；目录 embedding 是按 `normalized_name_hash + model + dimension + adapter_version` 持久化的受控语义缓存；查询向量只允许在同一次 Agent run 内内存复用，严禁跨 run 持久缓存。目录版本切换或资格变化必须进入缓存 key/失效条件。该阶段不需要生成模型或 reranker；若以后增加关系分类子任务，优先确定性规则或更便宜的小模型，但在新 SPEC 和冻结评测通过前不得进入权威选择链路。

## 5. Evaluation Strategy

### Dimensions

| Dimension | Rubric (Pass/Fail or 1-5) | Measurement Approach | Priority |
|-----------|--------------------------|---------------------|----------|
| 菜品身份与精确优先 | **PASS：**唯一当前合格 canonical name/受控 alias 只选择对应条目；冻结输入“米饭”返回 `PASS` 且选择米饭，不被“蛋炒饭”覆盖。**FAIL：**精确条目被模糊/向量排名改写，或把影响营养组成的加工、烹调、形态差异当作精确同一食物。 | Code：`exact_match_precision = 正确唯一精确 PASS 数 / 唯一精确用例数`，门槛 `1.0`；同时断言 selected `food_id + catalog_version`。Human：营养师复核新增高后果 exact/similar 标签。 | Critical |
| 非精确确认安全 | **PASS：**任何仅来自模糊文本或语义通道的结果都返回 `ASK`，即使只有一个或分数很高也不选择；无可靠候选允许返回空。**FAIL：**Top 1、相似度或候选数触发自动选择，或低质量候选被用于后续计算/记录。 | Code：`non_exact_auto_select_count = 0`，并对所有非精确/无结果用例校验 `selected_food_id is None`。 | Critical |
| 目录资格、来源与版本隔离 | **PASS：**候选均为当前可计算、未撤销、未失格且版本明确的受控条目，确认后可按 `food_id + catalog_version` 权威重读。**FAIL：**任一通道泄露旧版、撤销、失格、来源/营养字段不完整的条目，或只返回不可追溯显示名。 | Code：`ineligible_leak_count = 0`；真实 PostgreSQL 集成测试覆盖精确、文本、向量及确认后重读。 | Critical |
| 中文相关表达 Top 3 召回 | **PASS：**冻结的“西红柿炒鸡蛋→番茄炒蛋”“风干牛肉→牛肉干”“四川烤鱼→烤鱼”“定西土豆粉→土豆粉”“包子→生煎包”目标均进入最多 3 个候选，返回 `ASK`，不要求排第一。**FAIL：**稳定漏检、候选重复/超过 3 个，或仅因共享单一食材召回无关菜。 | Code：`top3_recall = Top 3 含标注目标的非精确用例数 / 有标注目标的非精确用例数`，冻结门槛 `1.0`。Human：中文菜系专家和目录管理员复核关系层及排除项；不引入 LLM Judge。 | High |
| 关系边界与用户可解释性 | **PASS：**候选按名称变体、地域/做法变体、同类成品菜分层，并只输出“名称相近”“地域/做法变体”“同类食物”等允许标签；可靠候选不足 3 个时不补位。**FAIL：**向量分数跨层压过更直接关系、暴露内部相似度，或用共享单一食材的候选凑数。 | Code：标签枚举、层级顺序、候选上限、去重和阈值断言。Human：每次冻结集变更由目录管理员与中文菜系专家抽审全部新增/修改关系标签。 | High |
| 降级、确定性与任务完成 | **PASS：**Embedding/向量查询超时、失败或索引缺失时，唯一精确仍可 `PASS`，文本候选仍以 `ASK` 返回；同一快照、查询和检索版本重复运行顺序相同，并在 Tool 时限内产生合法终态。**FAIL：**语义故障导致全链路失败、扩大 `PASS` 权限、排序漂移、重复候选或无界等待。 | Code：`fallback_success = 1.0`、`deterministic_order = 1.0`；Pydantic schema、候选唯一性/上限、超时与终态断言。 | Critical |
| 餐食分析/饮食规划语义一致 | **PASS：**两个 Agent 流程通过同一 Tool/Service，对相同查询、目录快照和检索版本产生相同候选 ID 顺序、`PASS/ASK`、selected ID 与关系标签。**FAIL：**任一流程绕过共享服务或出现不同的自动选择和候选语义。 | Code：每条冻结用例双入口回放；`flow_semantics_parity = 完全一致用例数 / 双入口用例数`，门槛 `1.0`。 | Critical |
| 隐私与可观测安全 | **PASS：**Embedding 仅收到规范化单项菜名；Phoenix 与可选 Langfuse 仅收到 allowlist 字段，查询文本/向量不持久化；Langfuse 逐例记录 30 天后删除。**FAIL：**导出真实用户身份、餐食、身体/健康数据、图片、完整 prompt、Provider 原文、密钥、思维链或查询向量。 | Code：Provider 请求 DTO、追踪导出器和 Langfuse 发布器的 allowlist/禁用路径测试，敏感字段 canary 必须零泄漏。Human：隐私与安全负责人发布前审查字段清单及 30 天删除证据。 | Critical |

六项锁定代码评分的发布阈值为：`exact_match_precision == 1.0`、`non_exact_auto_select_count == 0`、`top3_recall == 1.0`、`ineligible_leak_count == 0`、`fallback_success == 1.0`、`deterministic_order == 1.0`。此外，`flow_semantics_parity == 1.0` 是双 Agent 流程的独立硬门。任一分母为零、输入 hash 不匹配、实现/检索/embedding 版本缺失或证据不可读都必须 fail closed；不得跳过失败案例或通过重跑覆盖失败报告。

### Reference Dataset

**Size:** 实施开始时创建不少于 **24 条**版本化合成案例；进入发布门前保持至少 24 条且所有必需类别分母非零。后续只追加经审核的真实失败模式的合成复现，不复制真实用户输入。

**Composition:**

- 6 条唯一精确：canonical/alias、规范化边界、精确冲突；必须包含“米饭→米饭”并显式排除“蛋炒饭”误选。
- 6 条非精确相关表达：包含五个锁定映射，另含一个常见地域/做法变体；目标只要求进入 Top 3，全部必须 `ASK`。
- 4 条歧义、低质量和无结果：覆盖同名异物、仅共享单一食材、可靠候选不足 3 个、零候选，不允许凑数。
- 4 条资格/时态对抗：撤销、失格、旧版本、关键营养/来源字段缺失；各召回通道都不得泄漏。
- 4 条故障与确定性：Embedding 超时、Provider 合同失败、向量查询/索引缺失、重复运行稳定排序；验证文本降级不扩大权限。

每条案例都绑定 dataset schema/hash 链、固定 PostgreSQL 目录快照、期望动作、允许目标/排除 ID、目录版本、检索版本、embedding/Fake 版本和 `auto_pass_allowed`。所有 24 条都分别从餐食分析与饮食规划 Tool 入口回放，以计算 `flow_semantics_parity`；至少重复执行三次用于 `deterministic_order`，不得把精确同名条目塞入五个非精确 fixture 来绕过混合召回。

**Labeling:**

- 食品成分数据库编审/目录管理员标注稳定 ID、canonical/alias、资格、来源、当前版本、目标 ID 与排除 ID。
- 注册营养师标注加工、烹调、形态或配方差异是否足以禁止精确合并。
- 中文菜系专家复核地域名称、同义表达、关系层和“仅共享食材”的负例。
- 产品负责人确认唯一精确 `PASS`、其余 `ASK`/无结果的产品合同；隐私负责人确认 fixture、报告和可选 Langfuse 投影只含合成/去标识化 allowlist 字段。
- 代码直接对上述冻结标签评分，不使用 LLM Judge。任何标签或案例变更都必须新建 dataset version/hash、保留评测失败历史，并重新执行完整门禁；数据集在实现检索参数时同步建立和校准，不得等实现完成后倒推标签。

## 6. Guardrails

### Online (Real-Time)

| Guardrail | Trigger | Intervention |
|-----------|---------|--------------|
| 非精确禁止自动选择 | `action=PASS` 但 `match_channel != exact`，或非精确结果存在 `selected_food_id`，或 `PASS` 同时携带候选 | Pydantic/service invariant 立即 **Block**，返回安全追问/通用失败；记录 payload-free `error.code`，不得进入营养计算、记录或规划。 |
| 权威资格二次校验 | 任一候选物化或用户确认后重读发现条目已撤销、失格、非当前版本、来源/关键营养字段不完整 | 从候选中 **Block**；确认阶段使旧选择失效并 **Escalate** 为重新搜索/请用户重选，绝不使用索引快照作为授权。 |
| Embedding/向量安全降级 | Provider 超时、429/5xx、维度/数量/有限值合同失败、active vector space 不匹配或向量查询失败 | 立即停止语义通道并 **Fallback** 到精确/模糊文本；只有唯一精确仍可 `PASS`，其余保持 `ASK`；故障按安全错误码观测。 |
| 候选输出合同 | 候选超过 3 个、ID 重复、关系标签不在 allowlist、混合向量空间或结果 schema 无效 | **Block** 整个未校验结果，返回安全失败/重试；不得流式展示未过滤中间候选。 |
| 数据最小化出口 | Embedding DTO 含规范化单项菜名之外字段，或 Phoenix/Langfuse exporter 收到非 allowlist 字段、查询向量、敏感 canary | 在发送前 **Block**；Langfuse 发布整批失败，在线 tracing 丢弃非法字段并告警，禁止用日志兜底保存原文。 |

### Offline (Flywheel)

| Metric | Sampling Strategy | Action on Degradation |
|--------|------------------|----------------------|
| 六项锁定代码评分 + `flow_semantics_parity` | 每次检索实现、阈值、目录 schema、embedding model/dimension、融合或资格规则变更均对 100% 冻结集运行；定期夜间全量运行 | 任一硬门失败即阻止合并/发布；新增最小合成回归案例，版本化修复并保留失败报告。 |
| 关系层与候选相关性 | 每次冻结集变更人工审核 100% 新增/修改案例；每月复核全部高后果负例和五个锁定映射 | 暂停提升新 retrieval version；由营养师、目录管理员和中文菜系专家纠正标签/规则后重新跑全套门禁。 |
| 语义降级率、零候选率与索引滞后 | Phoenix 只收 100% payload-free 计数/延迟；按 retrieval/catalog/vector-space version 聚合，不保存查询 | 超阈值先检查 Provider、索引任务与版本切换；只把失效类型抽象为新的合成案例，不复制用户菜名。 |
| 用户确认后的改选/取消信号 | 仅聚合计数和版本；抽样复核由人工编写、去标识化的等价合成案例，不持久化真实查询或餐食 | 指标持续上升时审查关系阈值和别名治理；在冻结门通过前不得自动学习 alias 或放宽自动选择。 |
| Langfuse 实验完整性与隐私 | 每次显式发布检查 dataset/code/retrieval/embedding hash、成功/失败逐例 Score、allowlist 和 30 天保留策略 | 缺 hash、漏失败记录、含禁用字段或超期记录均判定实验证据无效并停止发布；不影响仓库评测器已给出的真实 PASS/FAIL。 |

## 7. Production Monitoring

**Tracing Tool:** **Arize Phoenix（现有默认）**，通过项目当前的私有 OpenTelemetry provider 和 allowlist-only span API 记录生产聚合信号；不启动进程内 Phoenix UI，也不导出菜名、用户/餐食/健康数据、候选正文、prompt、response 或思维链。**Langfuse（本地 Docker）**仅用于显式冻结数据集 Experiment：独立数据库、默认关闭、与在线请求解耦，详细 Trace/Score 保留 30 天；Git 永久保存数据集、汇总报告与 dataset/code/retrieval/embedding hashes。

**Key Metrics to Track:**

- 安全计数：`non_exact_auto_select_count`、`ineligible_leak_count`、DTO/allowlist 拒绝数，按 app/tool/retrieval/catalog version 聚合。
- 质量离线门：`exact_match_precision`、`top3_recall`、`fallback_success`、`deterministic_order`、`flow_semantics_parity`；只从冻结评测产生，不用无标签生产流量伪造准确率。
- 可用性：精确、hybrid、`text_fallback`、none 各通道请求数/成功率，Embedding/向量错误码与语义降级率。
- 延迟与成本：唯一精确、文本降级、含 Embedding 混合搜索的 p50/p95/p99，Provider token/调用/成本及 Tool 超时率。
- 索引健康：当前目录版本与 active vector space 一致性、待索引合格条目数、最老任务年龄、有限重试耗尽和手动重试次数。

**Alert Thresholds:**

- **立即告警并阻断发布/错误结果：** `non_exact_auto_select_count > 0`、`ineligible_leak_count > 0`、混合向量空间、敏感 canary 导出或任一冻结硬门低于阈值。
- **立即告警：** 生产结果 DTO invariant 失败、确认后权威重读失败，或 Langfuse/Phoenix 出口检测到非 allowlist 字段；非法内容必须已在发送前被阻断。
- **持续 15 分钟告警：** semantic degradation rate > 5%，或 hybrid Tool 超时率 > 2%；超过 20% 升级为严重故障，但继续执行安全文本降级。
- **持续 15 分钟性能告警：** 唯一精确 p95 > 50 ms、文本降级 p95 > 150 ms、含在线 Embedding 的非精确搜索 p95 > 1.5 s。上线前用目标区域压测复核这些初始 SLO，调整必须版本化并经冻结门批准。
- **索引告警：** 当前发布版本存在未索引合格条目超过 15 分钟时 warning，超过 60 分钟或有限重试耗尽时通知管理员手动重试；不能因此回滚已生效的精确/文本发布。

**Smart Sampling Strategy:**

在线安全不抽样：每个请求都执行 `PASS/ASK`、候选 schema/上限、资格与版本 guardrail，并只向 Phoenix 发出 allowlist 聚合属性。质量飞轮优先覆盖 100% 降级、合同拒绝、零候选、确认后失效、索引版本不一致和重复重选事件，再对其余成功通道按版本做不超过 5% 的 payload-free 指标抽样；这里的“抽样”不允许保存原始查询、查询向量或餐食上下文。

人工复核不直接读取生产菜名。维护者只依据错误类别、关系层、版本和聚合信号手工构造等价的去标识化/合成案例，经目录管理员与营养/中文菜系专家标注后追加到下一版冻结集。每个候选排序、阈值、目录版本或 embedding 版本变更都触发 100% 冻结集回放；可选 Langfuse 仅镜像该次冻结实验，成功和失败记录同样保留 30 天，且缺少 `--publish-langfuse` 时完全不产生 Langfuse 流量。
