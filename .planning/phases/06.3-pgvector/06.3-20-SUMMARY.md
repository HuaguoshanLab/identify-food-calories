# Phase 06.3 Plan 20: Hybrid Food Search Acceptance Summary

补齐混合菜品检索的中文可复现指南、真实后台 E2E 合同和只在隔离测试应用启用的受控 Fake embedding outcome 脚本；没有把 Langfuse 或真实 Provider 变成发布依赖。

## Completed Work

- 新增中文教学文档：精确优先、非精确 `ASK`/resume、current-qualified 检索、publication 聚合/retry、worker lease、证据绑定 activation、Phoenix/Langfuse 边界、30 天留存、启动/调试/冻结评测命令和常见错误。

## Blocked Acceptance

用户随后明确授权修复预存 lockfile 状态。`npm install --package-lock-only --ignore-scripts --no-audit --no-fund` 仅向 `frontend/package-lock.json` 补入 83 行既有依赖解析记录，`package.json` 未改；清除一次失败安装留下的可再生 `frontend/node_modules` 后，`npm ci --ignore-scripts --no-audit --no-fund` 成功安装 1,113 个锁定包。该修复单独提交为 `a16d61c`。

目标 Playwright 已两次实际启动隔离 Docker `postgres-test`、Mailpit、FastAPI、用户 SPA 和后台 SPA。第一次暴露 row-local 详情链接会硬导航并清除内存 access token，已改为项目既有 SPA 详情链接；第二次在干净 test DB 上完成真实注册/邮箱验证、first-admin bootstrap、后台登录、目录草稿、审核、发布和 `embedding-status` GET。但仍**不能通过**完整验收：发布后状态没有任何 job，20 次可见状态刷新均无法得到 `partial_failure`。

根因由代码确认：`AdminService._enqueue_catalog_embedding_jobs` 只会为已激活的 vector space 创建 job；干净隔离库没有 active space。后台当前也没有 vector-space build/activation 的页面入口。用数据库 seed、伪造/复制 Bearer token 或内部 service 调用来创建空间都违反本计划和 AGENTS 约束。因此以下项目未执行、未宣称通过：

- `admin embedding status and batch retry` 的完整 Playwright 断言（真实流程在可见 `partial_failure` 前被产品可达性缺口阻断）。
- Codex 内置浏览器的完整路径：`partial_failure → retry → 状态重放 → 降权普通用户 GET/POST 403`。内置浏览器已实际走用户注册/验证码页面，但测试服务清理后无法保留同一 isolated stack；不得以 DB/token/内部调用替代。
- 全仓 `uv run mypy app` 和后续串联的全量 PostgreSQL/release 命令：Ruff 全量通过，但 mypy 在本计划未触及的 records、dashboard、agent、admin、memory 与 evals 文件报告 107 个既有错误，命令按 fail-fast 未继续。计划文件范围内的 mypy 已通过。

恢复条件：需要明确架构决策并实现一个受数据库 RBAC、理由、审计和幂等保护的后台 vector-space build/activation 页面路径，或另行提供不依赖 token 复制且可从真实已登录产品页面触发的等价入口；之后重跑目标 Playwright，并用 Codex 内置浏览器走同一路径。

## Deviations from Plan

### Approved Architectural Correction

1. **[Rule 4 - Test-only Fake outcome injection]**
   - **Found during:** Task 1 E2E implementation。
   - **Issue:** 测试应用的 `FakeEmbeddingProvider` 默认所有未脚本调用均永久失败，公开目录发布无法同时获得 completed 与 failed job，不能生成真实 `partial_failure`。
   - **Fix:** 增加只接受 `success`、`permanent_failure` 的 test-only Settings/Factory/Fake seam，并由 Playwright test backend 环境显式配置 `success,permanent_failure,success`。
   - **Safety:** 非 test 环境含该变量即拒绝启动；不能传入 Provider body、回调、名称或任意错误码；默认 Fake 行为未改变。
   - **Authorization:** Parent executor explicitly approved Rule 4。

2. **[Rule 2 - User-visible status refresh]**
   - **Found during:** Task 1 RBAC browser-path design。
   - **Issue:** 现有页面自动初读状态，普通用户收到状态 GET 403 后无法再从页面触发 retry；也没有可见方式重读 status endpoint。
   - **Fix:** 增加不携带额外数据的“刷新嵌入构建状态”动作，并以两个真实已降权会话分别验证 GET 与 POST 边界，避免 token 复制/注入。

3. **[User-authorized pre-existing dependency repair]**
   - **Found during:** Task 1 Playwright startup。
   - **Issue:** `frontend/package-lock.json` 缺少现有 package graph 所需的 `gcp-metadata@7.0.1` 解析记录，`npm ci` 拒绝安装。
   - **Fix:** 用户明确授权后仅以 lockfile-only 模式同步，并以 `npm ci --ignore-scripts` 验证；未更改 `package.json`、未新增或升级产品依赖。
   - **Commit:** `a16d61c`。
