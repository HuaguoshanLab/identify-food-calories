## Reachability Check

- User query reaches the single `NutritionService.search_food_catalog` implementation only through the shared Agent Tool adapter.
- Every candidate reaches the user only after PostgreSQL qualification, DTO invariants and deterministic fusion.
- Publication creates exact/text visibility and multiple uniquely keyed name/vector-space jobs in one transaction; aggregate status derives from explicit job rows and one idempotent batch command retries failed rows.
- Controlled relation evidence reaches production through DB-RBAC/admin service create-version-revoke commands; repository projection joins only non-revoked evidence for both current publication versions and never changes candidate eligibility.
- Plan 04 creates the schema; the Plan 21 ADMIN-only build command creates the immutable target-space identity and exact current-qualified canonical/alias manifest plus jobs; Plan 10 reconciles those jobs and writes separate completion evidence only after exact snapshot coverage; Plan 17 validates both artifacts before activation.
- Frozen cases run actual repository, Tool and both Graph paths against an isolated real PostgreSQL snapshot; AdminService activation re-authorizes from PostgreSQL and validates report hashes plus exact build completion evidence before atomically switching the target space.
- `PersistedAgentRuntimeFactory` creates one Phoenix `TracingRuntime`, injects the same object into supervisor/adapters/every NutritionService, and application lifespan flushes/shuts it down once; spy-exporter integration proves only the six payload-free hybrid attributes leave the boundary.
- The targeted Playwright gate uses real login/product pages/public APIs to prove visible `partial_failure`, failed-job batch retry, idempotent repeat and ordinary-user 403, followed by built-in browser verification of the same path.
- Langfuse can only read the completed safe projection afterward; retention emits an ephemeral stdout/JSON result and persists no purge artifact.

## Pre-Mortem Controls

1. **False PASS or opaque candidates:** Plan 05 encodes the invariant and D-04 discriminator allowlist; Plans 13–14 preserve it through state/clarification before calculation/planning.
2. **Stale/partial index gains authority:** Plans 04/06/10/21 enforce immutable build snapshot, space, qualification, completion and lease contracts; Plans 16–17 require real-PG evaluation, DB-authorized activation and exact hash-bound evidence.
3. **Multi-job retry duplicates cost:** Plans 08–12 define one publication aggregate, explicit job rows and idempotent batch retry under partial/concurrent failure.
4. **Telemetry leaks payload or becomes authority:** Plan 07 constrains production Phoenix to payload-free attributes, Plan 16 writes the sole report, Plan 18 only mirrors it, and Plan 19 emits a bounded ephemeral purge result.
