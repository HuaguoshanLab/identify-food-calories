# Phase 06.1 — UI Design Contract

> 菜谱管理是后台的快速运营工具；按需加餐是用户 H5 已生成餐单的一张可选信息卡。两者共享数据语义，不共享布局或视觉皮肤。

---

## Scope and Page Inventory

| Surface | Route / component | User goal | Required outcome |
| --- | --- | --- | --- |
| Admin navigation | `/admin/*`, `AdminShell` | 找到菜谱管理 | “菜谱管理”置于“营养目录”之后，和既有一级导航同级。 |
| Recipe list | `/admin/recipes` | 查找、导入、维护候选 | 筛选栏 → 工具栏 → 当前页批量操作 → 可横向滚动表格 → 分页。 |
| Recipe import | dialog | 先看错误再确认导入 | 显示总行数、有效行数、逐行错误；有错误时确认按钮不可用。 |
| Bulk lifecycle | dialog | 启用、停用或软删除已选候选 | 显示数量、受影响范围、必填原因、逐项进度与可重试失败项。 |
| User plan | `PlanPage`, `MealCard` | 查看当天有效餐单 | 固定早餐/午餐/晚餐三卡；仅后端返回 `snack` 时追加“加餐”卡。 |
| Plan adjustment | `PlanPage` | 指定替换餐次 | 若计划带加餐，选择面板包含“加餐”；否则仅显示三主餐。 |

## Design System

| Property | Value |
| --- | --- |
| Tool | Tailwind CSS + existing shadcn/ui Base UI primitives |
| Preset | Existing admin neutral surface + H5 forest (`h5-forest-v1`) |
| Component library | Existing Base UI / local UI primitives only; no second UI library |
| Icon library | Lucide React only; emoji 不作为产品图标 |
| Font | Admin: `Inter, ui-sans-serif, system-ui, sans-serif`; H5: existing Chinese system sans stack |

### Design direction

- 后台采用现有中性蓝灰桌面管理界面：清晰边框、轻阴影、密集但不拥挤的数据表格。不得套用用户端森林绿移动壳。
- H5 延续可信、克制、生活化的森林绿主题，不将“加餐”做成高饱和奖励或健康评分。
- UI/UX 规范库建议的柔和层次、可见焦点、确认危险操作和表格横向滚动被采纳；其推荐的青色调和远程 Lora/Raleway 字体与项目既有视觉及“无远程字体”约束冲突，明确不采用。

## Spacing Scale

| Token | Value | Usage |
| --- | --- | --- |
| xs | 4px | 数值与单位、图标和短标签间隔 |
| sm | 8px | 表格操作、状态标签、紧凑表单字段 |
| md | 16px | H5 卡片内边距、后台表单字段、页面常规间隔 |
| lg | 24px | 后台区块内边距、筛选栏和表格工具栏 |
| xl | 32px | 后台页面/大区块间隔 |
| 2xl | 48px | 后台页面级分隔；不用于 H5 单屏堆叠 |

Exceptions: H5 Tab 根页水平安全边距遵从 `docs/ui/h5-foundation.md` 的 28px 壳层口径；后台 `.admin-runtime-root` 继续使用 32px 外边距；表格行使用现有 16px 垂直内边距以保证可读性。

## Typography

| Role | Admin | H5 | Usage |
| --- | --- | --- | --- |
| Body | 16px / 24px / 400 | 15px / 24px / 400 | 说明、候选名称和表单正文 |
| Label | 14px / 20px / 400–500 | 13px / 20px / 400 | 筛选、状态说明、辅助信息 |
| Heading | 20px / 28px / 600 | 16px / 24px / 600 | 页面标题、区块标题 |
| Display | 28px / 36px / 600 | 32px / 40px / 700 | 后台空态标题；H5 总热量（不新增加餐专用大数字） |

- 菜谱名称最长两行（详情/弹窗）或单行截断（表格）；悬停/聚焦可读取完整名称。
- 所有克数、营养、版本、日期、选中数量使用 `tabular-nums`，单位紧随数值。
- H5 餐次标题保持 `h3`：早餐、午餐、晚餐、加餐；不得因存在加餐跳过标题层级。

## Color

| Role | Admin value | H5 value | Usage |
| --- | --- | --- | --- |
| Dominant (60%) | `--background: oklch(0.985 0.003 264)` | `--background: hsl(140 20% 97%)` | 页面背景 |
| Secondary (30%) | `--card: oklch(1 0 0)` / `--muted` | `--card: #fff` / `--secondary: hsl(145 25% 94%)` | 卡片、表格、静态提示面 |
| Accent (10%) | `--primary: oklch(0.372 0.044 257)` | `--primary: hsl(152 40% 30%)` | 主按钮、当前导航、键盘焦点和已选行，不用于全部链接 |
| Destructive | Existing red alert/button semantic | `--destructive: hsl(0 65% 44%)` | 软删除确认、不可恢复风险说明、失败反馈 |
| Success | Existing emerald success feedback | `--success: hsl(152 45% 30%)` | 已启用、导入成功；必须同时有文字 |
| Warning | Existing amber warning feedback | `--warning: hsl(22 80% 36%)` | 待审核、可能影响计划的提示；必须同时有文字 |

状态不能只靠颜色：表格/弹窗显示完整文本“待审核”“已启用”“已停用”“已删除”；H5 加餐由标题“加餐”表达，不靠卡片颜色区分。

## Admin Recipe Management Contract

### Navigation and responsive behavior

- `AdminShell` 的一级导航顺序为：概览、营养目录、菜谱管理、运行审计、模型配置、操作审计。
- 在 `>=1280px` 侧栏完整显示；`1024–1279px` 使用现有紧凑侧栏；`768–1023px` 用现有导航 sheet；`<768px` 明确提示使用至少 768px 的设备完成完整后台操作。
- 候选表格必须放在可键盘聚焦的 `overflow-x-auto` 容器，保留列，不把表格改造成信息丢失的移动卡片。表头、勾选列和右侧操作列在滚动时保持现有可读性策略。

### List layout

1. 筛选栏：菜品名称/别名、餐次、状态；重置和“查询”作为唯一筛选确认动作。
2. 工具栏：`新增候选`、`导入`、`导出`、`下载模板`、刷新。主按钮仅为`新增候选`；导入/导出为次级按钮。
3. 批量操作栏：`已选 N 条`、`批量启用`、`批量停用`、`批量删除`、`清空选择`。只操作当前页已勾选项目，并明确提示此限制。
4. 表格列按以下顺序：勾选、关联目录菜品、餐次、单份克数、份量说明、做法标签、口味标签、状态、更新时间、操作。
5. 行操作：编辑、启用/停用（按当前状态显示其一）、删除、详情/审计。删除不和普通编辑同色，使用文字+破坏性语义。

### Import and bulk dialogs

- 导入弹窗标题为“导入菜谱候选”。文件选择后先显示“正在校验…”，随后显示“共 N 行，M 行可导入”。错误按`第 N 行 · 字段名 · 原因`展示；只要存在错误，确认导入不可点击。
- 成功文案：`已导入 N 条候选，当前均为待审核。` 不暗示它们已经可生成餐单。
- 启用确认文案：`启用 N 条菜谱候选？它们会进入之后生成的餐单。`
- 停用确认文案：`停用 N 条菜谱候选？之后生成的餐单不会再使用它们。`
- 删除确认文案：`删除 N 条菜谱候选？它们会立即从未来餐单中排除；已生成的餐单不受影响。`
- 三种批量操作都需要可见标签“操作原因”、最少 1 个非空输入值、提交期间禁用关闭/重复提交、逐项结果及原幂等键重试。401/403 立即停止剩余队列并展示登录/权限提示。

### Empty, error, and loading states

| State | Copy | Required action |
| --- | --- | --- |
| Empty | `暂无菜谱候选` | `下载模板后批量导入，或新增一条候选。` |
| Filter empty | `没有符合条件的候选` | 显示重置筛选按钮。 |
| Import error | `文件存在错误，暂未导入任何候选。` | 保留错误行列表和重新选择文件入口。 |
| Permission | `无后台访问权限` | `请使用管理员账号登录。` |
| Loading | `正在加载菜谱候选…` | 表格保留空间，按钮禁用，禁止闪烁空态。 |

## User H5 Optional Snack Contract

- 计划区标题统一为`今日饮食计划`，不再硬编码`今日三餐计划`。
- 餐次卡的固定显示顺序为早餐 → 午餐 → 晚餐 → 加餐（仅当 report 包含 `snack`）。不能显示空的“加餐占位卡”。
- 加餐使用同一 `MealCard` 结构：标题、能量小计、菜名、克数/份量、做法和口味标签；不新增独立加餐组件或特殊计算文案。
- 加餐存在时，全天总览仍以全部返回餐次总和展示；“总热量”和目标区间的含义不变。
- 调整输入提示保持`告诉我们想换什么`；槽位选择根据后端 `input_choices` 真实渲染，若包含 `snack` 则按钮文案为`加餐`。调整成功的无障碍播报为`已更新加餐，其余餐次保持不变。`
- 无候选或加餐导致校验不通过时，用户看到正常三餐计划，不显示“缺少加餐”错误或补齐诱导。
- H5 遵守现有 `100dvh` 单滚动区、四 Tab、不新增底部导航、安全区、44px 触控目标、可见焦点与 `prefers-reduced-motion` 规则。

## Accessibility and Interaction Requirements

- 所有输入有可见 `label`；placeholder 不能充当唯一标签。下拉框、复选框、表格行勾选和工具栏按钮都有准确的中文无障碍名称。
- 当前页全选 checkbox 在部分选择时设 `indeterminate`；键盘 Space 可切换。批量工具栏使用 `aria-label="批量操作"`。
- 弹窗打开时焦点移入标题/首个可操作元素，Escape 在非提交态关闭并回到触发按钮；提交中不可通过遮罩或 Escape 关闭。
- 危险状态、待审核、加载、成功和错误必须有文本，并可被 `role="status"` 或 `role="alert"` 感知。
- 按钮、链接和图标操作保持 40px 以上后台点击目标；H5 关键操作保持 44px。可点击元素使用稳定颜色过渡，不得用缩放导致表格或卡片位移。
- 表格数值列右对齐，表头使用 `scope="col"`；长列水平滚动不造成页面水平滚动。
