# Phase 06.1 Plan 01: 管理候选资格与可选加餐 Summary

**成品菜候选现在只关联可计算营养目录项；停用、软删除、未合格或营养不完整的候选在 SQL 查询层即被排除。**

## Accomplishments

- 新增 `managed_recipe_candidates` 与唯一的 0022 → 0023 Alembic 路径，记录餐次、固定克数、展示标签、状态、revision 和软删除时间。
- 候选 DTO 不含营养总量，营养必须继续经 `NutritionService.calculate_nutrition` 从关联目录项按克数重算。
- `MealSlot` 支持 `snack`，但主餐校验只强制早餐、午餐、晚餐；旧项目自有受控菜谱仍禁止加餐槽位，未放松原审核约束。
- 用 fake-domain 与真实 PostgreSQL 覆盖状态、软删除、目录资格、四项营养完整性和可选加餐边界。

- **Verification:** 51 个受影响规划测试通过。
