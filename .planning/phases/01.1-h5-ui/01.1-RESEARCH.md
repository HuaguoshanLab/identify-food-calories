## Summary

Phase 01.1 是前端结构迁移，不是新业务阶段。现有 FastAPI 已提供注册、验证、密码恢复、`/users/me`、会话列表、退出与撤销所需的全部公开契约；`CurrentUserResponse` 已包含 `email`、`is_active`、`role`，`SessionResponse` 已包含详情页所需的设备与时间字段，因此计划不得增加后端路由、Schema、migration 或数据库字段。[VERIFIED: `backend/app/auth/schemas.py`, `backend/app/auth/api.py`, `backend/app/accounts/api.py`]

安全的实现主线是：先修订跨阶段 UI 文档中的占位页冲突，再建立纯展示页面壳与纯路径常量；随后把 `/app/*` 组织为一个认证守卫下的嵌套路由树，Tab 根页使用 `AppShell`，账号/会话详情使用 `DetailLayout`，最后迁移公开页和认证表单。React Router 官方将无 path 的 layout route、嵌套路由与 `Outlet` 定义为共享布局的标准做法；`NavLink` 默认使用普通 history push，只有显式 `replace` 才会替换历史，并自动为活动链接暴露 `aria-current="page"`。[CITED: https://reactrouter.com/start/declarative/routing] [CITED: https://reactrouter.com/api/components/NavLink]

当前最值得提前处理的技术债有三项：`returnTo.ts` 只允许旧 `/app`；业务页面散落 `teal/slate/red/white` 与原生表单控件；`AlertDialog` 已使用 `bg-popover`/`text-popover-foreground`，但 `styles.css` 尚未映射或定义 `popover` token。[VERIFIED: `frontend/src/auth/returnTo.ts`, `frontend/src/auth/*.tsx`, `frontend/src/components/ui/alert-dialog.tsx`, `frontend/src/styles.css`] 视觉测试应建立在现有 Playwright 多 webServer、隔离 PostgreSQL 与 Mailpit 链路上，不另造 mock E2E；截图要显式固定 430×932、浅色、减少动态和稳定文件名，只 mask 动态日期，不 mask 结构或业务状态。[VERIFIED: `frontend/playwright.config.ts`, `frontend/tests/e2e/auth-skeleton.spec.ts`] [CITED: https://playwright.dev/docs/test-snapshots]

**Primary recommendation:** 以“文档冲突修订 → 语义 token 与 shell → 精确路由白名单 → 页面迁移 → 组件/路由测试 → 真实 E2E/视觉基线 → 内置浏览器验收”的顺序规划；不新增依赖，不碰后端协议。

### System Architecture Diagram

```text

        ↓
React Router route table
  ├─ public route
  │    ↓
  │  PublicAuthLayout → MobileFrame → PageScrollArea → public/auth page
  │
  └─ /app or /app/*
```

### Pattern 1: One guard, nested layout routes

**What:** 用一个 pathless `RequireAuthentication` layout 包住所有 `/app/*`；内部再按 `AppShell` 与详情页拆 layout route。React Router 官方说明父/无 path route 可通过 `Outlet` 渲染子路由，index route 可表达默认子页。[CITED: https://reactrouter.com/start/declarative/routing]

**When to use:** 所有受保护页面共享相同身份启动，但视觉壳不同。

```tsx
// Source: https://reactrouter.com/start/declarative/routing
<Route element={<RequireAuthentication />}>
  <Route path="/app">
    <Route index element={<Navigate replace to="/app/me" />} />
    <Route element={<AppShell />}>
      <Route path="analyze" element={<PlaceholderTabPage title="分析" />} />
      <Route path="records" element={<PlaceholderTabPage title="记录" />} />
      <Route path="plans" element={<PlaceholderTabPage title="计划" />} />
      <Route path="me" element={<MePage />} />
    </Route>
    <Route path="me/account" element={<AccountDetailsPage />} />
    <Route path="me/sessions" element={<SessionsDetailsPage />} />
  </Route>
</Route>
```

守卫组件应渲染 `<Outlet />`；只有 `/app` index redirect 使用 `replace`，Tab 的 `NavLink` 不传 `replace`。[CITED: https://reactrouter.com/api/components/Outlet] [CITED: https://reactrouter.com/api/components/NavLink]

### Pattern 2: Exact returnTo allow-list

**What:** URL 先按同源基准解析，再拒绝外部 origin、反斜杠、hash 和未登记 pathname；只允许 `/app` 与六个明确子路径。不要把 `startsWith('/app')` 当安全边界，因为它也会接受未来/伪造路径。[VERIFIED: `frontend/src/auth/returnTo.ts`] [CITED: https://github.com/OWASP/ASVS/blob/master/5.0/docs_en/OWASP_Application_Security_Verification_Standard_5.0.0_en.flat.json]

**When to use:** 未登录深链跳登录、登录成功回原页面。

```ts
const protectedPaths = new Set([
  '/app',
  '/app/analyze',
  '/app/records',
  '/app/plans',
  '/app/me',
  '/app/me/account',
  '/app/me/sessions',
])

// Keep current origin/hash/backslash checks; then require exact pathname membership.
```

登录页完成认证后继续 `navigate(returnTo, { replace: true })` 是正确的：它替换登录页，不影响之后 Tab 点击的正常 push 历史。[VERIFIED: `frontend/src/auth/LoginPage.tsx`] [CITED: https://reactrouter.com/api/components/NavLink]

### Pattern 3: Shell owns overflow; content owns scrolling

**What:** `MobileFrame` 是 `flex-column + overflow-hidden`；`PageScrollArea` 是唯一 `flex:1; min-height:0; overflow-y:auto`；header 与 bottom nav 是普通 flex siblings，不用 `position:fixed` 锚到浏览器视口。[VERIFIED: `01.1-UI-SPEC.md`]

**When to use:** 全部公开页、Tab 根页和详情页。

关键结果：手机端 frame 为 `100dvh` 全屏；桌面外层仍是 430px 设备容器；底部导航不覆盖最后一个控件；`body` 不与 main 同时滚动。[VERIFIED: `docs/ui/h5-foundation.md`]

不要用 `md:` 改变设备容器内部的内容列数或 padding。桌面 viewport 虽然大于 768px，内部 H5 仍只有 430px；viewport breakpoint 会让“同样 430px 的手机与桌面预览”出现不同内部布局。[VERIFIED: `docs/ui/h5-foundation.md`]

### Pattern 4: Complete semantic token pairs, dark class reserved

**What:** 根 CSS 在 `@theme inline` 暴露 `background/foreground`、`card`、`popover`、`primary`、`secondary`、`muted`、`accent`、`destructive`、`border`、`input`、`ring`；`:root` 与 `.dark` 都定义本阶段使用的 token 对。业务组件只写 `bg-background`、`text-muted-foreground`、`border-border` 等语义 utility。[CITED: https://ui.shadcn.com/docs/theming]

**When to use:** styles 基座及所有迁移页面。

```css
/* Source: https://ui.shadcn.com/docs/theming */
@custom-variant dark (&:is(.dark *));

@theme inline {
  --color-popover: var(--popover);
  --color-popover-foreground: var(--popover-foreground);
  /* keep all existing semantic mappings */
}

:root { /* official light semantic values */ }
.dark  { /* official dark semantic values; no toggle in Phase 01.1 */ }
```

当前 `AlertDialog` 依赖 `popover`，所以补齐它不是品牌扩展，而是修复现有官方原语的主题合同。[VERIFIED: `frontend/src/components/ui/alert-dialog.tsx`, `frontend/src/styles.css`] 深色预留只包含 token 和 class variant；不增加 Provider、localStorage、系统偏好监听或切换按钮。[VERIFIED: `01.1-UI-SPEC.md`]

### Pattern 5: Preserve behavior while replacing presentation

**What:** 认证页继续使用原 React Hook Form、Zod schema、错误映射和 API 函数，只把外壳、原生控件和硬编码颜色迁移到 `PublicAuthLayout` 与现有 `Input/Label/Button/Alert`。[VERIFIED: `frontend/src/auth/LoginPage.tsx`, `RegisterPage.tsx`, `RegisterVerifyPage.tsx`, `ForgotPasswordPage.tsx`, `ResetPasswordPage.tsx`]

**When to use:** 首页和七类公开/认证页面。

规划应把“业务行为测试先固定/迁移”与“视觉样式替换”放在同一波次，避免先大改 JSX 再猜 Phase 1 行为。尤其不得重写验证码冷却、恢复 context、single-flight refresh 或退出警告。[VERIFIED: `frontend/src/auth/AuthForms.test.tsx`, `AuthSession.test.tsx`, `AuthProvider.tsx`]

### Pattern 6: Real-data visual fixture with explicit stability controls

**What:** 新 `h5-visual.spec.ts` 复用公开注册 → Mailpit 取码 → 验证 → 登录 → 第二浏览器登录链，固定 visual 邮箱和串行顺序；截图前等待可观察 UI 稳定，mask 仅覆盖动态日期。[VERIFIED: `frontend/tests/e2e/auth-skeleton.spec.ts`] [CITED: https://playwright.dev/docs/test-snapshots]

```ts
// Source: https://playwright.dev/docs/test-snapshots
test.use({
  viewport: { width: 430, height: 932 },

  reducedMotion: 'reduce',

await expect(page).toHaveScreenshot('h5-me.png', {
```

### Anti-Patterns to Avoid

- **每条页面手动包守卫和壳：** 会产生底部导航/详情页错配和重复 bootstrap；使用一个守卫加嵌套 layout route。[CITED: https://reactrouter.com/start/declarative/routing]
- **Tab 点击 `replace`：** 会破坏 D-05 的浏览器返回历史；普通 `NavLink` 即可。[CITED: https://reactrouter.com/api/components/NavLink]
- **详情返回只写 `navigate(-1)`：** 直接深链可能没有安全的上一个站内历史；使用确定的 `/app/me` 语义链接。[CITED: https://reactrouter.com/api/hooks/useNavigate]
- **`startsWith('/app')` returnTo：** 不是精确授权白名单；必须按解析后的 pathname exact match。[VERIFIED: `frontend/src/auth/returnTo.ts`]
- **底部导航 CSS fixed 到 viewport：** 桌面预览会脱离 430px frame，且增加遮挡补偿；用 frame 内非滚动 flex sibling。[VERIFIED: `01.1-UI-SPEC.md`]
- **内部页面使用 `md:` 变桌面版：** breakpoint 看外部 viewport，不看 430px frame；会让同尺寸 H5 在手机和桌面表现不同。[VERIFIED: `docs/ui/h5-foundation.md`]
- **直接写 `teal/slate/red/white`：** 破坏深色预留和统一状态语义；业务组件只用 token。[VERIFIED: `01.1-UI-SPEC.md`]
- **重新 init/overwrite shadcn：** 可能覆盖已验证的 Base UI 原语和 Phase 1 调整；本阶段只组合已有源码。[VERIFIED: `01.1-UI-SPEC.md`]
- **用 Toast 承担字段错误：** 违反 D-11；字段错误必须贴字段，跨字段/服务端错误在表单顶部。[VERIFIED: `01.1-CONTEXT.md`]
- **为占位 Tab 放 CTA、Skeleton 或样例数据：** 会把未交付能力伪装成可用；严格保持标题 + 状态说明。[VERIFIED: `01.1-CONTEXT.md`]
- **截图时 mock API 或直接 seed DB：** 不能证明 Cookie、Mailpit 和会话撤销；组件测试才允许 mock。[VERIFIED: `01.1-CONTEXT.md`]
- **默认测试自动带 `--update-snapshots`：** 会把真实回归覆盖成新基线；先正常失败并审查 diff，再显式更新。[CITED: https://playwright.dev/docs/test-cli]
- **把 `reuseExistingServer` 改成 true 规避端口冲突：** 会复用未知进程并让 E2E 假绿；保留 false，测试前清理明确拥有的进程。[VERIFIED: `frontend/playwright.config.ts`]

## Common Pitfalls

### Pitfall 1: New routes bypass authentication
**What goes wrong:** `/app/me/account` 等直接深链能渲染页面，或 unauthenticated returnTo 被丢失。  
**Why it happens:** 只保护旧 `/app` element，没有用一个父守卫包住全部子路由。  
**How to avoid:** pathless guard + nested `/app` tree；对每个子路径做 401→login→原路径回跳测试。[CITED: https://reactrouter.com/start/declarative/routing]  
**Warning signs:** 子页单独写 `RequireAuthentication`，或 `returnTo.ts` 仍只有 `/app`。[VERIFIED: current code]

### Pitfall 2: The device frame has two scroll owners
**What goes wrong:** body 和内容区同时滚、底部 Tab 随内容移动、最后按钮被安全区遮挡。  
**Why it happens:** 继续沿用每页 `min-h-dvh`，又在新 shell 内添加 `overflow-y-auto`。  
**How to avoid:** 页面子组件不再声明 viewport main；只有 MobileFrame 定高，只有 PageScrollArea 滚动。[VERIFIED: `01.1-UI-SPEC.md`]  
**Warning signs:** auth/page JSX 仍出现 `min-h-dvh`、`md:px-*` 或多个 `<main>`。[VERIFIED: current code grep]

### Pitfall 3: Theme utilities silently have no token
**What goes wrong:** 弹窗背景/文字样式缺失，dark 预留只是文档。  
**Why it happens:** Tailwind v4 只有暴露在 `@theme` 的 token 才产生对应 utility；当前缺 `popover` mapping/value。[CITED: https://tailwindcss.com/docs/theme] [VERIFIED: current CSS/components grep]  
**How to avoid:** 先列出现有官方原语使用的 token，再补齐 `@theme inline`、`:root`、`.dark` 三处。  
**Warning signs:** `bg-popover` 存在但 `--color-popover`/`--popover` 搜索为空。

### Pitfall 4: Responsive classes react to desktop viewport, not 430px frame
**What goes wrong:** 同样 430px 宽的 H5 在手机和桌面设备容器内排版不同。  
**Why it happens:** `md:` 根据 browser viewport 触发，不根据 frame 宽度。  
**How to avoid:** 内容保持单列和一致 padding；只对 MobileFrame 外观使用 `md:`，会话按钮可以始终纵向。[VERIFIED: H5 contract]  
**Warning signs:** app/auth content 出现 `md:grid-cols-*`、`md:px-*`、`md:flex-row`。

### Pitfall 5: Session empty state lies
**What goes wrong:** API 返回 `[]` 时页面说“只有当前设备保持登录”，把异常状态当正常。  
**Why it happens:** 当前实现只检查 `otherSessions.length === 0`，没有检查 `currentSession`。[VERIFIED: `frontend/src/auth/SessionList.tsx`]  
**How to avoid:** `currentSession` 存在且 others 为空才显示正常空态；完全空数组显示异常空态 + retry。[VERIFIED: `01.1-UI-SPEC.md`]  
**Warning signs:** `sessions=[]` 测试仍命中“暂无其他登录会话”。

### Pitfall 6: Visual tests are either flaky or fake
**What goes wrong:** 日期/字体造成无意义 diff，或为了稳定直接 mock/静态渲染 protected 页面。  
**Why it happens:** 没固定 viewport/environment，或把稳定性误解为绕过真实链路。  
**How to avoid:** 同一 Playwright/browser/OS、固定 430×932、fixed email、reduced motion、可观察等待；只 mask 动态日期。[CITED: https://playwright.dev/docs/test-snapshots]  
**Warning signs:** `waitForTimeout`、随机 email 出现在截图、mask 整张卡片、MSW 出现在 E2E。

### Pitfall 7: Snapshot update becomes the default test
**What goes wrong:** 任何回归都被自动写入 Git baseline。  
**Why it happens:** package script 内置 `--update-snapshots` 或 executor 看到 diff 直接 `-u`。  
**How to avoid:** 默认 `npm run test:e2e` 永不更新；先查看 expected/actual/diff，确认后再显式 `--update-snapshots=changed`，随后再正常运行。[CITED: https://playwright.dev/docs/test-cli]  
**Warning signs:** CI/verify 脚本包含 `-u`。

### Pitfall 8: Existing green unit suite still has async warning noise
**What goes wrong:** 真正的 React act warning 被大量既有 bootstrap warning 淹没。  
**Why it happens:** public route tests挂载 AuthProvider 后不等待它的 refresh state update。[VERIFIED: local `npm test -- --reporter=dot`, 29 tests pass with warnings]  
**How to avoid:** public route测试不挂不需要的 provider，或统一 stub refresh 并等待稳定状态；Phase 01.1 完成门禁要求 stderr 无 act warning。  
**Warning signs:** 测试退出 0 但 stderr 持续出现 “not wrapped in act(...)”。

### Pitfall 9: Documentation indexes drift during file moves
**What goes wrong:** 代码通过但目录合同测试/项目规则失败。  
**Why it happens:** 新增 `app/`、`layouts/`、snapshot 目录或移动 RouteGuards 内容时未同步 README。  
**How to avoid:** 每个结构任务把 README/index 更新列为同一原子提交的一部分。[VERIFIED: `AGENTS.md`]  
**Warning signs:** `rg --files` 有新目录但无 README，或 auth README 仍说 `/app` 是组合账号页。

```tsx
  ))}
</nav>
```

`NavLink` 会自动为 active link 添加 `aria-current="page"`；不要重复手写或用颜色作为唯一状态。[CITED: https://reactrouter.com/api/components/NavLink]

```ts
await expect.poll(() => page.evaluate(() => ({
  client: document.documentElement.clientWidth,
  scroll: document.documentElement.scrollWidth,

```

如果浏览器 scrollbar 或 device emulation 使 exact width 不稳定，可断言 `scroll <= client` 而不是放宽为截图肉眼观察。[ASSUMED]

### Known Threat Patterns for React SPA auth migration

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| Open redirect via `returnTo` | Spoofing | parse URL against fixed origin、reject hash/backslash、exact pathname allow-list；测试外域、`//`、未知路径。[VERIFIED: current tests + recommended migration] |
| Protected child route omitted from guard | Elevation of Privilege | one parent authentication layout route covering every `/app/*`; direct-deep-link tests.[CITED: https://reactrouter.com/start/declarative/routing] |
| Token accidentally persisted during UI refactor | Information Disclosure | AuthProvider/API modules不改 token storage；测试继续检查 local/session storage 无 token。[VERIFIED: `AuthSession.test.tsx`] |
| UI says revoke succeeded while card remains/action still active | Repudiation / Tampering UX | 后端 204 后 invalidate Query、移除卡片、status 播报；错误时 dialog 保持打开。[VERIFIED: UI-SPEC] |
| Snapshot leaks email/token/code | Information Disclosure | 固定 `.test` 邮箱；不截图 Mailpit 正文、Cookie、token 或验证码；动态日期只 mask DOM surface。[VERIFIED: project security rules] |
| Fake admin/nav surface | Elevation of Privilege | wildcard route仍不注册 `/admin`，route tests断言无 admin link/probe。[VERIFIED: existing Public/Protected route tests] |
