# Phase 01.1: H5 UI 基座与现有页面迁移 - Context

**Gathered:** 2026-08-28
**Status:** Ready for planning

<domain>
## Phase Boundary

本阶段在不修改后端业务协议的前提下，为 `frontend/` 建立统一的移动端 H5 页面基座，并迁移 Phase 1 已交付的首页、认证流程、账号资料与登录会话页面。交付内容包括页面壳、四 Tab 导航、独立滚动区、安全区、shadcn 语义 token、深色主题预留、代表性视觉回归和真实浏览器验收。本阶段只允许明确标记的未开放 Tab 占位页，不实现 Agent 分析、餐食记录、饮食计划或后台管理业务。

</domain>

<decisions>
## Implementation Decisions

### 四 Tab 呈现与路由

- **D-01:** Phase 01.1 即展示“分析、记录、计划、我的”四个底部 Tab；四项分别使用 `ScanLine`、`NotebookText`、`CalendarDays`、`UserRound` 图标。
- **D-02:** “分析、记录、计划”当前为明确占位页，每页只显示对应页面标题和“功能即将开放”状态说明；不得出现假数据、假按钮、模拟分析结果或可用性暗示。
- **D-03:** 四个 Tab 使用独立路径：`/app/analyze`、`/app/records`、`/app/plans`、`/app/me`。刷新页面后保留当前 Tab。
- **D-04:** Phase 01.1 的 `/app` 默认重定向到 `/app/me`，因为“我的”是当前唯一真实可用的 Tab；Phase 2 上线分析能力后再把默认入口调整为“分析”。
- **D-05:** 点击 Tab 使用正常浏览器历史记录；返回键按用户访问顺序返回，不使用无条件 replace 抹掉 Tab 访问历史。
- **D-06:** 本讨论对未开放 Tab 的决定覆盖 `docs/ui/h5-foundation.md` 当前“不要提前画空壳 Tab”的旧表述。Phase 01.1 计划必须先同步该文档，再实现代码；覆盖范围仅限上述诚实占位页，不允许伪造业务能力。

### 首页与认证页统一

- **D-07:** 首页、登录、注册、邮箱验证码、找回密码、重置密码、隐私和条款页面全部迁入统一的 `MobileFrame` 与 `PublicAuthLayout`，不只替换局部颜色。
- **D-08:** 首页保持一个明确主操作：“创建账号”使用主按钮，“登录”使用次级按钮。用户确认现有首页截图表达的视觉层级正确。
- **D-09:** 登录、注册和找回密码等入口页面显示品牌入口；验证码和重置密码等后续步骤显示返回按钮，返回目标必须对直接打开深链的用户仍然有效。
- **D-10:** 注册与密码恢复流程显示简洁文字进度，例如“步骤 1/2”“步骤 2/2”，不使用偏重的进度条。
- **D-11:** 字段校验错误紧贴对应输入框；网络或服务端错误位于表单顶部；成功后跳转到目标页面并通过状态消息反馈。不得用 Toast 代替全部错误定位。

### “我的”信息结构

- **D-12:** `/app/me` 使用纵向设置列表，只展示“账号资料”和“登录会话”两个真实入口；每项包含 Lucide 图标、标题、简短说明和右侧箭头。
- **D-13:** “账号资料”进入独立只读详情页，显示邮箱、账号状态和角色；本阶段没有资料修改 API，因此不提供编辑按钮或本地假保存。
- **D-14:** “登录会话”进入独立详情页，并在列表内直接提供“退出当前设备”和“撤销其他会话”操作；撤销继续使用确认弹窗，保留 Phase 1 已交付行为。
- **D-15:** 账号资料和登录会话详情页使用 `DetailLayout`，显示顶部返回按钮并隐藏底部四 Tab。

### UI 测试与真实验收

- **D-16:** 视觉回归以 430px 为截图基线；320px 和桌面设备容器尺寸执行布局、遮挡与无横向滚动检查，不为每个视口复制全部截图。
- **D-17:** 代表性截图覆盖首页、登录、注册、一个未开放 Tab、“我的”、账号资料、登录会话及撤销弹窗。共享同一布局的其他认证路由只做行为与结构测试。
- **D-18:** Playwright 和 Codex 内置浏览器验收必须使用真实后端、公开 API 与 Mailpit 完成注册、验证、登录和会话路径；不得通过直接写数据库、伪造 token 或只使用 MSW 冒充跨栈验收。MSW 仅用于组件测试。
- **D-19:** 截图基线进入 Git。差异出现时必须先人工审查，确认属于预期设计变化后才能更新；禁止测试自动覆盖基线。

### the agent's Discretion

- 在不改变上述信息架构和交互语义的前提下，决定占位说明、入口辅助文案和空状态的具体措辞。
- 决定基础组件的内部文件拆分、Tailwind 类组合和测试辅助函数，但必须复用现有 shadcn 原语，不引入第二套组件库。
- 决定 Playwright 截图文件的稳定命名和复用 setup，只要真实跨栈路径与人工更新门禁不被削弱。

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets

- `frontend/src/components/ui/` 已包含 `Button`、`Card`、`Input`、`Label`、`Alert`、`AlertDialog`、`Badge`、`Separator` 和 `Skeleton`，本阶段应直接复用并建立页面壳，不重新手写第二套原语。
- `frontend/src/auth/AuthProvider.tsx`、`useAuth.ts` 和 `RouteGuards.tsx` 已提供浏览器身份恢复、受保护路由和登出行为，UI 迁移不能绕过这些状态边界。
- `frontend/src/auth/SessionList.tsx` 与 `RevokeSessionDialog.tsx` 已实现真实会话列表、刷新、退出和撤销确认，可拆入登录会话详情页。
- `frontend/src/auth/PublicPages.tsx` 已有首页、隐私和条款内容，可迁入 `PublicAuthLayout` 而不改业务含义。

### Established Patterns

- React Router 管理公开与受保护路由；Tab 应使用真实链接和独立路径，而不是组件内临时状态。
- React Hook Form + Zod 管理认证字段校验；TanStack Query 管理会话查询与失效刷新。
- Tailwind CSS v4 与 shadcn Base UI 已安装，主题从 `frontend/src/styles.css` 的语义变量进入组件。
- Vitest/Testing Library 覆盖组件与路由行为，Playwright 已有真实认证骨架和固定端口测试约束。

### Integration Points

- `frontend/src/App.tsx` 需要接入 AppShell、四个 Tab 路由、`/app` 重定向和两个详情页。
- 现有 `AuthEntryPage`/`PublicPage` 是 `PublicAuthLayout` 的迁移入口；现有账号与会话组合页需要拆成“我的”根页面和两个详情页。
- `frontend/src/styles.css` 是 shadcn 默认语义 token、设备容器、页面视口和深色主题预留的唯一根级入口。
- `frontend/tests/e2e/` 承载真实跨栈行为与 430px 截图基线；组件级 MSW 不得替代这些路径。

</code_context>

<specifics>
## Specific Ideas

- 用户确认当前首页截图中绿色“创建账号”与描边“登录”的主次关系正确，迁移后应保持该信息层级，但颜色改为 shadcn 语义 token 而非散落硬编码。
- 未开放页面的核心不是“看起来已经做好”，而是让四 Tab 地基可见且诚实告知功能尚未开放。
- 本阶段先把 H5 UI 地基做稳，再进入 Phase 2 的 Agent 核心开发。

</specifics>
