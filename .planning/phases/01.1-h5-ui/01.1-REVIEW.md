## Warnings

### WR-01: 动作阶段收到失效验证 context 时被错误地伪装成网络故障

**File:** `/Users/mina/Documents/ChatGPT/identify-food-calories/frontend/src/auth/RegisterVerifyPage.tsx:98-100,147-149,163-175`  
**Classification:** WARNING  
**Issue:** 提交验证码或重发请求返回 `VERIFICATION_CONTEXT_INVALID` 时，代码只设置外层 `invalidContext` state。随后的渲染分支重新声明了同名局部变量，并且只检查 `contextQuery.error`；此前 context 查询成功时它是 `false`。因此页面显示“暂时无法连接服务”并只提供一次无意义的 context refetch，而不是显示“验证信息已失效”及“返回注册”。用户无法按设计契约恢复注册流程。现有测试只覆盖初始 context 查询失败，漏掉了两个动作 API 的失效 context 分支。

**Fix:** 使用不重名的 `contextInvalid` / `queryContextInvalid` 状态，并在 `!pending` 分支以两者的逻辑或决定文案和 `/register` 链接；为 `verifyRegistration` 与 `resendRegistrationCode` 分别增加 `VERIFICATION_CONTEXT_INVALID` 回归测试。

### WR-02: 密码重置把可恢复的网络故障错误告知为恢复信息失效

**File:** `/Users/mina/Documents/ChatGPT/identify-food-calories/frontend/src/auth/ResetPasswordPage.tsx:27-30`  
**Classification:** WARNING  
**Issue:** `verifyRecoveryCode` 或 `resetPassword` 抛出的 `NETWORK_ERROR`、5xx 映射的 `UNKNOWN_ERROR`、以及 CSRF 来源错误都会被统一显示成“恢复信息已失效，请重新开始”。这既是错误诊断，也会诱导用户放弃仍然有效的 HttpOnly recovery context；页面没有保留可重试当前提交的入口。该文件的测试没有覆盖网络错误或第二个 reset 请求失败。

**Fix:** 按错误码分支：`INVALID_RECOVERY_CODE` 保持字段级提示；`NETWORK_ERROR` / `UNKNOWN_ERROR` 显示网络/服务错误并提供对同一已验证表单的重试；仅 `RECOVERY_CONTEXT_INVALID`、过期和尝试耗尽显示重新申请链接。为“验证成功后 reset 网络失败”及“首次网络失败”分别添加测试。

### WR-03: “我的”和详情路由未把焦点移到新页面的 h1

**File:** `/Users/mina/Documents/ChatGPT/identify-food-calories/frontend/src/app/MePage.tsx:7-27` and `/Users/mina/Documents/ChatGPT/identify-food-calories/frontend/src/layouts/AppHeader.tsx:13-27`  
**Classification:** WARNING  
**Issue:** UI-SPEC 要求路由变化后将焦点移动到新页面 `h1`。`PlaceholderTabPage`、公开页已经这么做，但“我的”页的 h1 没有 `tabIndex={-1}`/focus effect，详情页标题同样不可程序聚焦。点击底部“我的”或从“我的”进入账号/会话详情后，键盘和读屏用户不会得到新的页面标题公告；当前测试只验证占位页与公开页焦点，未覆盖这三个真实受保护页面。

**Fix:** 抽取一个只在路由内容挂载时执行的 heading focus hook，或在 `MePage` 和 `AppHeader` 为 h1 加 ref、`tabIndex={-1}` 和 `useEffect(...focus())`；新增从 Tab 进入“我的”、从“我的”进入账号/会话详情后的焦点断言。
