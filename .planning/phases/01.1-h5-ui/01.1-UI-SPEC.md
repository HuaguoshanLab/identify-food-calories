# Phase 01.1 — H5 UI Design Contract

> Phase 01.1 的视觉与交互实现依据。规划器和执行器必须同时读取本文件、`01.1-CONTEXT.md` 与 `docs/ui/h5-foundation.md`；发生冲突时，Context 中的阶段定向决定优先。

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn/ui |
| Preset | `base-nova`（来源：`frontend/components.json`） |
| Component library | Base UI，`@base-ui/react` 1.7.0 |
| Styling | Tailwind CSS v4 + CSS semantic tokens |
| Icon library | Lucide React；不得混用 Emoji 或第二套图标 |
| Font | 系统无衬线栈；本阶段不加载远程字体 |
| Theme | shadcn 默认浅色语义 token；预留 `.dark`，不实现主题开关 |
| Visual direction | 可信、克制、清爽、生活化；最小单列、低阴影、单一主操作 |

### Existing primitives

只复用官方 shadcn 原语：`Button`、`Card`、`Input`、`Label`、`Alert`、`AlertDialog`、`Badge`、`Separator`、`Skeleton`。页面壳和业务组合组件可以新增，但不得复制一套按钮、输入框或弹窗原语，也不得引入第二套组件库。

### Research resolution

- 采用 `ui-ux-pro-max` 的 Minimal Single Column、单一 CTA、明确错误恢复、匹配内容尺寸的 Skeleton、正常浏览器历史和可见焦点建议。
- 不采用其 Vibrant & Block-based、金色品牌色、远程 Figtree/Noto Sans、scroll-snap 和大幅动画建议；这些与项目已锁定的 shadcn 默认 token、系统字体和克制型 H5 方向冲突。
- 不新增营养图表、食物卡片、Agent 对话或未来功能演示图。Phase 01.1 只建立可承载这些能力的 UI 地基。

## Spacing Scale

Phase 01.1 新增样式只能从以下 4px 网格取值：

| Token | Value | Usage |
|-------|-------|-------|
| `xs` | 4px | 图标与文字的紧凑间距 |
| `sm` | 8px | 字段内部、内联元素和紧凑列表间距 |
| `md` | 16px | 常规页面横向 padding、列表 gap、卡片 padding 和设置行间距 |
| `lg` | 24px | 标题与主体、主要区块之间的间距 |
| `xl` | 32px | 首页与认证页大区块间距 |
| `2xl` | 48px | 仅用于长页面的主区段分隔 |
| `3xl` | 64px | 底部导航主体高度，不作为随机页面 margin |

Exceptions:

- 44px 是关键触控目标和主按钮最小高度，不是额外 spacing token。
- 52px/60px 是紧凑/常规顶部栏高度，64px 是底部导航主体高度。
- 20px/22px 是图标尺寸；430px/932px 是设备容器尺寸。上述尺寸不得被当作业务组件间距复用。
- 跨阶段规范曾允许额外细分值，但 Phase 01.1 不把它们作为间距 token；紧凑上下文使用 8px，常规页面 padding、列表 gap 和卡片 padding 使用 16px。

## Typography

本阶段只声明 4 个字号和 2 个字重；组件不得自行增加字号或字重。

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Supporting / Tab | 12px | 400 | 16px |
| Body / Field / Label | 16px | 400 或 600 | 24px |
| Section heading | 20px | 600 | 28px |
| Page display | 28px | 600 | 36px |

- 每页只有一个 `h1`，使用 Page display；区块标题使用 Section heading。
- 卡片标题、字段标签和主要按钮使用 16px/600；正文使用 16px/400；辅助说明和 Tab 使用 12px/400。
- 输入文字固定不小于 16px，避免 iOS 聚焦时缩放。
- 只允许 400 和 600 两种字重；不使用 500/700 制造额外层级。
- 邮箱、设备名允许换行；日期、倒计时和未来营养数值使用 `tabular-nums`。

## Color

本阶段不冻结品牌 Hex。所有值都通过 shadcn 语义 token 引用，禁止在业务组件写 `slate-*`、`teal-*`、`red-*`、十六进制色值或 `white/black`。

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `background` + `foreground` | 页面背景、正文和大面积基础表面 |
| Secondary (30%) | `card`、`secondary`、`muted`、`border` | 卡片、列表行、导航、辅助说明和弱分割 |
| Accent (10%) | `primary` + `primary-foreground` + `ring` | 当前页面唯一主操作、当前 Tab、键盘焦点 |
| Destructive | `destructive` | 撤销其他会话和撤销确认；不用于普通错误正文 |

Accent reserved for:

- 首页“创建账号”；
- 每个认证表单当前步骤的提交按钮；
- 底部导航当前 Tab 的图标与文字；
- 输入和交互控件的可见焦点环；
- 成功状态不靠主色单独表达，必须配合明确文字或图标。

`destructive` 只用于“撤销其他会话”及其确认动作。退出当前设备使用次级/描边按钮，因为它不是删除账号，也不能与远端会话撤销混淆。网络错误、警告和成功消息使用 `Alert`/边框/图标/文字形成语义，不新增私有红黄绿色板。

## Layout Contracts

### Shared hierarchy

```text
Browser viewport
└─ MobileFrame
   ├─ PublicAuthLayout
   │  └─ PageScrollArea
   ├─ AppShell
   │  ├─ optional AppHeader
   │  ├─ PageScrollArea (main)
   │  └─ BottomNavigation (4 tabs)
   └─ DetailLayout
      ├─ AppHeader (back + title)
      └─ PageScrollArea (main)
```

### `MobileFrame`

- 小于 768px：宽高占满视口，主高度使用 `100dvh`，不得出现设备圆角、外阴影或 `body` 与内容区双滚动。
- 大于等于 768px：容器宽 `min(430px, calc(100vw - 2rem))`，高 `min(932px, calc(100dvh - 2rem))`，居中，32px 圆角、1px `border` 和单层轻阴影。
- 容器固定 `display:flex; flex-direction:column; overflow:hidden`。页面内容只允许 `PageScrollArea` 纵向滚动，并设置 `flex:1; min-height:0; overflow-y:auto`。
- 顶部使用 `env(safe-area-inset-top)`；底部导航、弹窗操作区使用 `max(基础间距, env(safe-area-inset-bottom))`。

### `PublicAuthLayout`

- 用于 `/`、全部认证页面、`/privacy` 和 `/terms`；绝不显示底部 Tab。
- 短内容可在设备容器内垂直居中；一旦高度不足必须自然滚动，不能压缩输入框或按钮。
- 入口页显示“饮食健康 Agent”品牌入口并链接 `/`；后续步骤显示 44×44px 返回按钮和确定的返回目标。
- 表单宽度占满内容区，不创建桌面双栏认证页。

### `AppShell`

- 只用于四个 Tab 根页面；底部导航固定，内容不能被 64px 导航及安全区遮挡。
- 提供可聚焦的“跳到主要内容”链接；主内容容器有稳定 `id`。
- Tab 使用真实 `NavLink`/链接和正常 push 历史；只有 `/app` 到 `/app/me` 的索引重定向可以 replace。
- 详情页不嵌套 AppShell，不同时显示返回栏和底部 Tab。

### `DetailLayout`

- 用于账号资料和登录会话详情页。52px 顶部栏包含返回 `/app/me` 的 44×44px 链接和单行标题。
- 底部四 Tab 隐藏；页面仅保留一个纵向滚动区。
- 本阶段详情页没有固定底部提交栏；会话操作位于对应会话卡内。

## Route and Navigation Contract

| Route | Layout | Heading | Navigation behavior |
|-------|--------|---------|---------------------|
| `/app` | protected index | none | replace 到 `/app/me` |
| `/app/analyze` | AppShell | 分析 | Tab 点击 push；刷新保留路径 |
| `/app/records` | AppShell | 记录 | Tab 点击 push；刷新保留路径 |
| `/app/plans` | AppShell | 计划 | Tab 点击 push；刷新保留路径 |
| `/app/me` | AppShell | 我的 | Phase 01.1 默认真实入口 |
| `/app/me/account` | DetailLayout | 账号资料 | 顶部返回 `/app/me`，无底部 Tab |
| `/app/me/sessions` | DetailLayout | 登录会话 | 顶部返回 `/app/me`，无底部 Tab |

- 四个底部 Tab 固定顺序和图标：分析 `ScanLine`、记录 `NotebookText`、计划 `CalendarDays`、我的 `UserRound`。
- 当前项使用 `aria-current="page"`，视觉变化只包含 `primary` 色和 600 字重，不增加胶囊背景或悬浮中央按钮。
- 每项图标 22px、标签 12px；整项命中区域覆盖其四等分单元且不小于 44px 高。
- 未认证访问任何 `/app/*` 深链时跳到 `/login?returnTo=...`；登录成功后必须回到原路径。允许列表需从旧 `/app?tab=*` 迁移为上述真实路径。
- 浏览器返回键按访问顺序工作。例如“我的 → 记录 → 计划”返回到“记录”；不得在 Tab 点击时使用 replace。

### Honest placeholders

`/app/analyze`、`/app/records`、`/app/plans` 的内容严格只有：

1. 对应 `h1`：“分析”/“记录”/“计划”；
2. 状态说明：“功能即将开放”。

不显示 CTA、示例卡片、假数字、模拟结果、骨架屏、上传入口或任何“看似可用”的控件。本阶段的此项锁定决定定向覆盖 `docs/ui/h5-foundation.md` 中“不要提前画空壳 Tab”的旧表述；实现计划必须同步修订该跨阶段文档。

## Page Contracts

### Landing `/`

从上到下固定为：

1. 品牌文字“饮食健康 Agent”；
2. `h1`“拍下或描述一餐，获得可追问的饮食分析”；
3. 说明“登录后使用餐食分析、记录和规划功能。结果仅作普通饮食参考。”；
4. 全宽主按钮“创建账号”；
5. 全宽次级按钮“登录”；
6. 文本链接“查看隐私说明”“查看使用条款”。

不增加上传按钮、演示结果或未来能力假入口。按钮视觉主次保持用户已确认的现有层级，但颜色全部迁移到语义 token。

### Authentication pages

| Route | Header | Progress | Primary CTA | Secondary navigation |
|-------|--------|----------|-------------|----------------------|
| `/login` | 品牌入口 | none | 登录并继续 | 忘记密码？ / 创建账号 |
| `/register` | 品牌入口 | 步骤 1/2 | 发送验证码 | 返回登录 |
| `/register/verify` | 返回 `/register` | 步骤 2/2 | 验证并激活账号 | 重新发送验证码 / 返回修改邮箱 |
| `/forgot-password` | 品牌入口 | 步骤 1/2 | 发送重置验证码 | 返回登录 |
| `/reset-password` | 返回 `/forgot-password` | 步骤 2/2 | 更新密码 | 重新申请重置 |
| `/privacy` | 品牌入口 | none | none | 返回首页 |
| `/terms` | 品牌入口 | none | none | 返回首页 |

- 文字进度位于标题上方，使用 12px `muted-foreground`，格式固定为“步骤 1/2”或“步骤 2/2”；不使用进度条。
- 每个字段保留可见 `Label`，并关联 `id`、`aria-describedby`、`aria-invalid`、正确 `autocomplete` 和 `inputMode`。
- 同一表单只有一个主提交按钮。异步提交时按钮保留宽高，文案切换为“正在…”，禁用重复提交但不得让禁用态成为唯一反馈。
- 字段错误紧贴字段下方并进入 `aria-describedby`；网络/服务端错误使用表单顶部 `Alert` 和 `role="alert"`；成功消息在目标页使用 `role="status" aria-live="polite"`。
- 入口页和后续页的返回目标必须支持直接深链：没有历史记录时仍能回到 `/register` 或 `/forgot-password`，不能只调用 `navigate(-1)`。
- 验证码为 6 位数字输入，使用 `inputMode="numeric"` 和 `autocomplete="one-time-code"`；冷却倒计时使用 `tabular-nums`，按钮文案明确剩余秒数。

### My root `/app/me`

页面只包含 `h1`“我的”、一句简短说明和一个纵向设置列表：

| Entry | Icon | Supporting copy | Destination |
|-------|------|-----------------|-------------|
| 账号资料 | `CircleUserRound` | 查看邮箱、账号状态与角色 | `/app/me/account` |
| 登录会话 | `MonitorSmartphone` | 查看并管理已登录设备 | `/app/me/sessions` |

- 每行是完整语义链接，不是在 `div` 上绑定点击；包含 20px 左图标、标题、辅助说明和 20px `ChevronRight`。
- 行高由内容决定，但整体命中区不小于 56px；内部紧凑元素使用 8px，设置行 padding 与行间距使用 16px，并用 1px 弱分割，不给每行重阴影。
- 不在根页面重复展示邮箱、角色、退出按钮、长期偏好或未来设置入口。

### Account details `/app/me/account`

- 使用只读 `dl`，依次显示“邮箱”“账号状态”“角色”。邮箱允许断行。
- `is_active=true` 显示“正常”；角色映射为“普通用户”或“管理员”，不直接把 `user/admin` 当最终界面文案。
- 不显示编辑、保存、上传头像或修改邮箱按钮；后端没有这些协议，伪造本地编辑属于越界。
- 身份正在恢复时使用匹配三行资料的 Skeleton；恢复失败显示“无法加载账号信息”与“重新尝试”。

### Sessions details `/app/me/sessions`

- 列表顺序固定为当前会话在前、其他会话按后端顺序排列。
- 每个会话卡显示设备名称、当前设备文字标记、最近活动、到期日期及一个明确操作。
- 当前会话使用次级按钮“退出当前设备”；其他会话使用 destructive 按钮“撤销会话”。320px 下操作按钮换到信息下方并占满可用宽度，不挤压日期或设备名称。
- 撤销成功后关闭弹窗、重新获取列表、移除已撤销卡片，并在列表标题附近播报“登录会话已撤销。”；成功后不得继续显示该卡的“撤销会话”按钮。
- 退出当前设备先清理本地身份并进入登录页；服务器确认失败时，登录页顶部显示现有退出警告，不让用户误以为其他设备也已退出。

## State Contracts

| Surface | Loading | Empty | Error | Success |
|---------|---------|-------|-------|---------|
| Auth bootstrap | MobileFrame 内身份 Skeleton +“正在确认登录状态…” | unauthenticated 跳登录 | “无法加载账号信息”+“重新尝试” | 进入原 protected route |
| Auth form | 按钮原位加载，不改变布局 | not applicable | 字段就近；服务端位于表单顶部 | 目标页状态消息 |
| Account details | 三行资料 Skeleton | not applicable | 内容区错误 +“重新尝试” | 只读资料 |
| Sessions | 两张与最终卡片同尺寸 Skeleton | 当前会话存在但无其他会话时显示“暂无其他登录会话” | `Alert`：“无法加载登录会话。请检查网络后重新尝试。”+“重新尝试” | 撤销后状态播报并刷新 |
| Placeholder tabs | not applicable | 标题 +“功能即将开放” | not applicable | not applicable |

### Sessions empty copy

- Heading: “暂无其他登录会话”
- Body: “只有当前设备保持登录。新的设备登录后会显示在这里。”
- 如果 API 连当前会话都未返回，不伪造成正常空态；显示“暂时没有可显示的登录会话。”和“重新尝试”。

### Destructive dialog states

- Title: “撤销这个登录会话？”
- Body: “该设备将需要重新登录。此操作不会删除账号或饮食数据。”
- Cancel: “保留这个会话”
- Confirm: “撤销这个会话”
- Pending: “正在撤销…”；关闭动作在请求期间禁用。
- Failure: 弹窗内 `role="alert"` 显示“无法撤销这个登录会话。请检查网络后重新尝试。”，弹窗保持打开，允许再次确认或取消。
- 关闭弹窗后焦点返回触发“撤销会话”的按钮；键盘 Escape 行为必须保留。

## Accessibility Contract

- 页面路由变化后把焦点移动到新页面 `h1`（`tabIndex=-1`），但不显示无意义的长期焦点样式；弹窗关闭后恢复到触发按钮。
- AppShell 有可见于聚焦状态的跳转链接；键盘顺序为顶部 → 主内容 → 底部导航，和视觉顺序一致。
- 交互元素必须使用 `button`/`a`/`nav`/`main` 等原生语义，不使用可点击 `div`。
- 所有纯图标按钮有明确 `aria-label`；返回按钮命名为“返回我的”。
- `BottomNavigation` 使用 `nav aria-label="主要导航"`，当前项通过 `aria-current="page"` 暴露，不只靠颜色。
- 表单错误使用 `role="alert"` 或被字段 `aria-describedby` 引用；成功和倒计时变化使用克制的 `aria-live="polite"`，不得每秒抢占式播报。
- 文本与背景达到 WCAG AA 4.5:1，大字 3:1；焦点环清晰且不被容器 `overflow` 裁切。
- 所有关键点击区域至少 44×44px；320px 和 200% 缩放下不得水平滚动、遮挡按钮或截断操作文案。
- 支持 `prefers-reduced-motion`；颜色、透明度和轻位移反馈为 150–200ms，减少动态时关闭非必要动画。

## Responsive Contract

| Viewport | Contract |
|----------|----------|
| 320×800 | 全屏 H5；表单、列表和会话按钮单列；无水平滚动或底部遮挡 |
| 375px wide | 检查键盘、表单错误、固定导航和内容滚动 |
| 430×932 | 主设计与截图基线；移动端全屏，无设备外框 |
| 768px wide | 430px 设备容器居中；容器外背景可见；无平板拉伸 |
| 1024/1440px wide | 仍为同一 430px H5 设备容器；验证阴影、边框和鼠标/键盘交互 |
| 200% zoom | 仍只有一个主滚动区；标题、设置行和会话操作不重叠 |

- 页面内容不得通过固定像素高度挤进一屏；空间不足时只滚动 `PageScrollArea`。
- 底部导航主体 64px 并叠加安全区；滚动内容末尾必须有相等补偿，最后一个控件可完整滚入视口。
- 页面内滚动条可在移动端弱化；桌面设备容器保留可感知的滚动反馈。

- Protected 页面和会话弹窗必须通过真实注册 → Mailpit 读取验证码 → 验证 → 登录 → 第二设备登录的公开链路准备；MSW 只能用于组件测试。

- 每次 E2E 使用隔离测试库、固定测试邮箱和可重复顺序。会话日期等不可冻结的后端动态文本可在截图断言中用 Playwright `mask` 定点遮罩，但 DOM、布局和公开 API 仍必须真实。
- 截图前等待网络与页面状态稳定，关闭非必要动画；不得用任意 sleep 代替可观察状态。
- 基线文件进入 Git。差异只能在人工查看 diff 并确认是预期设计变化后更新；测试命令禁止自动覆盖基线。

### Non-screenshot checks

- 320px：全部代表性页面检查 `scrollWidth <= clientWidth`、按钮不遮挡、会话卡纵向排布。

- 浏览器历史：四 Tab 顺序返回；详情返回我的；登出后后退仍受保护。
- Codex 内置浏览器最终走一次真实首页 → 注册 → Mailpit 验证 → 登录 → 四 Tab → 我的 → 会话撤销/退出路径，并记录地址、观察结果和未覆盖项。
