## 文字餐食的解析与追问节奏

### 自然份量处理

| Option | Description | Selected |
|--------|-------------|----------|
| 接受受控常见份量 | 有明确目录换算时直接换算，没有可靠换算时追问 | ✓ |
| 始终要求克数 | 精确但高频打断日常输入 | |
| 自动采用默认份量 | 省交互但会制造不可靠假设 | |

**User's choice:** 接受受控常见份量。

### 多个阻塞字段的追问方式

| Option | Description | Selected |
|--------|-------------|----------|
| 单轮集中追问 | 先展示整餐清单，再集中询问全部阻塞字段 | ✓ |
| 每轮只问一个字段 | 对话简单但往返过多 | |
| 每轮只处理一个菜品 | 机械且容易丢失整餐上下文 | |

**User's choice:** 单轮集中追问所有阻塞字段。

### 用户修正方式

| Option | Description | Selected |
|--------|-------------|----------|
| 自然语言定向修正 | 保留其他确认项，只重算受影响项 | ✓ |
| 重新提交整餐 | 实现简单但丢失已确认信息 | |
| 固定编辑命令 | 稳定但不像自然对话 | |

**User's choice:** 自然语言定向修正。

### 计算前确认

| Option | Description | Selected |
|--------|-------------|----------|
| 信息完整时直接计算 | 只在缺失或歧义时 interrupt | ✓ |
| 每次计算前确认 | 固定增加一次无效交互 | |
| 首次确认后记住偏好 | 需要 Phase 4 长期偏好能力 | |

**User's choice:** 信息完整且无歧义时直接计算。

## 模糊菜名与目录外食物的处理

### 多候选匹配

| Option | Description | Selected |
|--------|-------------|----------|
| 展示最多 3 个候选 | 给出关键区别并由用户确认 | ✓ |
| 自动选最高匹配项 | 快但可能产生可信的错误结果 | |
| 不唯一就拒绝 | 过度保守，浪费可用候选 | |

**User's choice:** 展示少量候选并让用户选择。

### 别名自动归一化

| Option | Description | Selected |
|--------|-------------|----------|
| 唯一受控别名自动匹配 | 登记等价词可自动映射，推断只做候选 | ✓ |
| 模糊相似度自动匹配 | 追问少但误映射风险高 | |
| 所有别名都确认 | 连明确等价词也反复打断 | |

**User's choice:** 只自动匹配唯一受控别名。

### 初始营养目录规模

| Option | Description | Selected |
|--------|-------------|----------|
| 小型可追溯 MVP 种子目录 | 覆盖演示与冻结测试，保留来源/授权/版本 | ✓ |
| Phase 2 建设大规模菜品库 | 会吞噬 Agent 核心阶段范围 | |

**User's choice:** 小型、真实、版本化、可追溯的 MVP 种子目录。

**Notes:** 用户指出当前没有现成营养目录。讨论明确：不要求用户准备数据；研究阶段核实合法数据源，Phase 2 建立初始目录。

### 目录外食物

| Option | Description | Selected |
|--------|-------------|----------|
| 改名、选候选或排除 | 未知项不估算，其他项目继续计算并标注缺口 | ✓ |
| 终止整餐分析 | 一个未知项导致整餐无结果 | |
| 模型估算 | 违反确定性营养真相边界，不可采用 | |

**User's choice:** 允许排除未知项并生成明确标注的部分结果。

## 文本分析结果与会话收口

### 结果粒度

| Option | Description | Selected |
|--------|-------------|----------|
| 逐项明细加整餐汇总 | 可追溯且直接提供整餐价值 | ✓ |
| 只显示整餐汇总 | 无法定位错误项 | |
| 只显示逐项明细 | 用户必须自己累计 | |

**User's choice:** 逐项明细 + 整餐汇总。

### 展示精度

| Option | Description | Selected |
|--------|-------------|----------|
| kcal 取整，宏量 1 位小数 | 可读且避免虚假精确 | ✓ |
| 全部取整 | 小份量差异可能消失 | |
| 全部 2 位小数 | 与份量误差不匹配 | |

**User's choice:** 热量取整，宏量营养保留 1 位小数。

### 校验异常

| Option | Description | Selected |
|--------|-------------|----------|
| 按严重度分流 | 重算、追问、阻止或提示均由确定性规则决定 | ✓ |
| 始终展示并警告 | 可能传播已知错误数字 | |
| 任意异常都终止 | 轻微提示也导致无结果 | |

**User's choice:** 按严重度分流。

### 会话收口

| Option | Description | Selected |
|--------|-------------|----------|
| 完成本轮但允许同线程修正 | 新餐开新线程，保存留到 Phase 4 | ✓ |
| 报告后锁定线程 | 发现错误只能重做 | |
| 等用户确认才完成 | Phase 2 没有保存语义，确认价值不足 | |

**User's choice:** 报告生成即完成，但允许同线程定向修正。

## 运行状态、失败反馈与断线恢复

### SSE 内容

| Option | Description | Selected |
|--------|-------------|----------|
| 稳定业务阶段事件 | 结构化状态和安全摘要，不暴露思维链 | ✓ |
| 逐 Token 模型文本 | 中间内容不稳定且可能泄露推理 | |
| 只返回最终结果 | 长操作没有进度反馈 | |

**User's choice:** 稳定、版本化的业务阶段事件。

### 断线恢复

| Option | Description | Selected |
|--------|-------------|----------|
| 自动重连并恢复线程快照 | 同一 thread_id，不重复调用或计费 | ✓ |
| 用户点击继续 | 网络抖动也需要人工介入 | |
| 重跑整条链路 | 重复调用、重复计费且违反 Checkpoint 目标 | |

**User's choice:** 自动重连并恢复线程快照。

### 自动重试

| Option | Description | Selected |
|--------|-------------|----------|
| 瞬时故障自动重试一次 | 受总预算约束，确定性失败不重试 | ✓ |
| 全部手动重试 | 一次网络抖动也会打断 | |
| 自动重试到成功 | 费用和循环不可控 | |

**User's choice:** 只自动重试瞬时故障一次。

### 预算耗尽与终止反馈

| Option | Description | Selected |
|--------|-------------|----------|
| 明确终止状态与下一步 | 安全失败类别、保留输入、提供补充或重试 | ✓ |
| 统一显示分析失败 | 用户无法判断如何恢复 | |
| 展示技术错误 | 泄露内部实现与敏感细节 | |

**User's choice:** 明确终止状态并给出可操作下一步。

## Planning Clarification：数据保留

计划校验发现运行数据保留期尚未锁定，因此在 plan-phase 中补充确认。

| Option | Description | Selected |
|--------|-------------|----------|
| 分层保留 | Checkpoint/SSE 7 天、最小审计元数据 30 天、用户删除后 24 小时内级联清理 | ✓ |
| 全部保留 30 天 | 恢复窗口更长，但保存更多短期状态和事件数据 | |
| 全部保留 7 天 | 数据最小化最强，但审计与较晚恢复能力更弱 | |

**User's choice:** 分层保留。

**Notes:** Provider 结果未知时固定进入 `PROVIDER_OUTCOME_UNKNOWN` 且不自动重试；未经营养专业复核的中文“一碗/一份”换算不得发布。
