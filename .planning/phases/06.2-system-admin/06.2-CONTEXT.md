# Phase 06.2: System Admin：系统管理与角色治理 - Context

**Gathered:** 2026-09-08
**Status:** Ready for planning

<domain>
## Phase Boundary

本阶段在独立 `admin-frontend/` 后台增加一级菜单“系统管理”，下设“管理员管理”和“角色管理”。管理员管理通过公开 `/api/v1/admin/*` 接口查看账号并执行管理员晋升、降权；角色管理解释现有固定 `user/admin` 角色及权限范围。

本阶段补齐现有“数据库实时 RBAC、管理员晋升与审计仅存在于后端/CLI，缺少后台 HTTP 与 UI”的断层。范围不包括自定义角色、动态权限点、组织/租户、用户健康数据管理、密码重置或会话管理。

</domain>

<decisions>
## Implementation Decisions

### 导航与页面结构

- **D-01:** 后台主导航新增一级分组“系统管理”，二级页面固定为“管理员管理”和“角色管理”；继续使用现有可折叠侧边栏、面包屑和多标签页壳。
- **D-02:** “管理员管理”允许展示全部账号及邮箱，并支持按邮箱、账号状态和角色筛选；接口只返回管理所需身份字段，不返回密码、会话、健康资料、餐食、Agent 原文或其他业务数据。
- **D-03:** “角色管理”在 v1 只读展示固定 `user/admin` 两种角色、权限说明和账号数量，不提供创建、编辑、删除角色或权限点的假入口。

### 管理员角色变更

- **D-04:** 管理员可将已验证、有效的普通账号晋升为管理员，也可将其他管理员降为普通用户；每次变更必须填写原因，并展示明确的二次确认。
- **D-05:** 禁止管理员修改自己的角色，禁止撤销系统中最后一个有效管理员；并发请求也必须由数据库事务/锁保证不能绕过最后管理员保护。
- **D-06:** 角色变更必须在一次事务内写入角色和不可变审计证据，使用幂等键并返回可审计结果；前端不得自行伪造成功。
- **D-07:** 管理员降权后立即失去全部后台访问权限，即使持有旧 access token 也不例外；后端每次请求继续从 PostgreSQL 读取当前角色，不能相信 JWT role 或前端状态。
- **D-08:** 降权后保留该账号现有普通用户登录会话，不强制退出用户端；后台前端必须清理该身份的管理员缓存并进入无权限页。
- **D-09:** 首位管理员 bootstrap 继续保留为 CLI 运维能力，不在网页中提供“无管理员时自助提权”。

### the agent's Discretion

- 确定账号列表的分页方式、默认排序、最小筛选字段、加载/空态文案和移动端表格降级方式，但必须满足全账号可见和数据最小化边界。
- 确定角色权限说明的具体分组、只读矩阵和统计查询方式；不能暗示系统支持尚不存在的细粒度权限。
- 确定角色变更 API 的 DTO、并发锁、版本/冲突语义、错误码和缓存失效策略；必须保持 API → Service → Repository → Model 分层与现有审计格式。

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets

- `AdminService.require_role`：所有后台读取与写入前重新读取 PostgreSQL 当前角色，可直接延续旧 token 立即失权语义。
- `AdminService.promote_admin` 与 `_commit_promotion`：已有有效/已验证目标校验、行锁、原因和原子审计，但当前仅由 CLI 调用。
- `AdminRoleAudit` / `AdminAuditEvent`：已有专用角色迁移证据和通用后台审计，可用于统一展示角色变更。
- `admin-frontend/src/features/audit/`：已有筛选表单、分页表格、Zod 响应校验和失败态模式。
- `AdminSidebar` / `AdminTabs`：现有导航分组、折叠、移动抽屉、面包屑与访问页签模式。

### Established Patterns

- 后台仅调用公开 `/api/v1/admin/*`；页面不直接 `fetch`，每个 feature 的 `api/` 负责 HTTP 与 Zod DTO。
- 前端路由守卫和菜单只改善体验，后端数据库实时角色才是授权真相。
- 角色写入和审计必须同事务成功或回滚；并发敏感操作需数据库锁和明确冲突响应。
- 页面/表单/路由改动需要 Vitest + MSW、HTTPX、真实 PostgreSQL集成、Playwright 和内置浏览器实际路径验证。

### Integration Points

- 在 admin repository/service/api 增加最小账号列表、角色统计、晋升和降权能力；不建立平行的 user-management 模块绕过现有 admin 审计。
- 在 `admin-frontend/src/features/` 新增独立系统管理 feature，并同步更新自身、父级与布局 README 索引。
- 在 `adminNavigation.ts` 增加“系统管理”组，在 `App.tsx` 注册两个受现有 `AdminRouteGuard` 保护的路由。
- 降权当前登录管理员或角色 probe 变为 403 时沿用认证层的管理员缓存清理和 forbidden 路径。

</code_context>

<specifics>
## Specific Ideas

- 用户明确允许管理员管理页暴露全部账号邮箱，而非只展示管理员后通过精确邮箱添加。
- 用户明确要求降权后保留普通用户登录会话，仅撤销后台访问。
- 用户确认采用固定两角色、角色页只读、禁止自降权和最后管理员降权的推荐范围。

</specifics>

<deferred>
## Deferred Ideas

- 自定义角色、权限点、角色 CRUD 与动态权限矩阵 — 需要新的授权模型、迁移和全端权限映射，当前没有产品需求依据。
- 普通账号启用/停用、密码重置和会话强制退出 — 属于完整用户账号治理，不在本阶段管理员角色管理范围内。

</deferred>
