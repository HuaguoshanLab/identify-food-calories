# Phase 06.2：系统管理 UI Contract

## Information architecture

- 侧边栏第一个一级分组为“系统管理”，默认展开。
- 二级入口依次为“管理员管理”“角色管理”，使用现有 Lucide 图标、面包屑和后台壳。

## 管理员管理

- 标题下明确说明页面用途；筛选区包含邮箱、角色、状态与查询。
- 表格展示邮箱、角色、状态、注册时间和操作；窄屏允许表格区域横向滚动，页面本身不产生额外横向滚动。
- 当前管理员自己的按钮禁用；未验证或停用普通账号不可提升。
- 角色变更弹窗展示目标邮箱、影响说明和必填原因；取消按钮获得初始焦点。
- 成功反馈必须包含前后角色和“操作已记录”；409 显示可理解的冲突信息。

## 角色管理

- 只读展示管理员、普通用户的说明、账号数和真实权限范围。
- 明确说明当前不支持自定义角色或权限点，不出现无效编辑按钮。

## 权限失效

- 查询遇到 401/403 时清理后台内存会话并显示无权限状态。
- 降权保留普通用户认证会话，但任何后台 API 都必须立即返回 403。

## Accessibility

- 输入控件有显式 label，表格使用语义元素，状态和错误使用 `role=status/alert`。
- 弹窗具备标题、说明、焦点陷阱和关闭后的焦点恢复。
- 颜色不是唯一状态信号；按钮禁用态同时具备原生 `disabled`。
