# Phase 06.2：Existing Patterns

## Backend

- `backend/app/admin/service.py`：继续使用 `require_role` 作为数据库实时 RBAC 入口，以 Service 作为事务边界。
- `backend/app/admin/repository.py`：沿用 SQLAlchemy 查询、`with_for_update` 和 PostgreSQL advisory lock。
- `backend/app/admin/models.py`：复用 `AdminRoleAudit` 与 `AdminAuditEvent`，不引入重复审计模型。
- `backend/app/admin/api.py`：沿用 403 JSON 响应以及 404/409 的明确策略错误映射。

## Admin frontend

- `admin-frontend/src/features/audit/`：复用 feature 私有 API、Zod 严格解析、TanStack Query 筛选和表格模式。
- `admin-frontend/src/layouts/adminNavigation.ts`：导航、标题和面包屑共用同一数据源。
- `admin-frontend/src/components/ui/AlertDialog.tsx`：危险角色变更使用现有焦点受控确认弹窗。
- `admin-frontend/src/auth/AdminAuthProvider.tsx`：401/403 清理管理员内存态，不自行决定权限。
