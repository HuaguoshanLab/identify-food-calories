<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| browser-declared timezone → records confirmation | 浏览器值只能经 records 既有 ZoneInfo 验证与一次确认写入，不能直接决定 dashboard query。 |
| dashboard service → records-owned preference | dashboard 只经最小 tenant-scoped read Port 读取当前统计依据，不写 preference、不重算历史行。 |
| user local window → weekly review graph | local current date 必须在 facts/coverage/cache/provider 之前确定；Provider 不获得 zone、原始餐食或用户身份。 |
| API client → week_start validation | week_start 是不可信输入；服务以已确认的用户 zone 验证 Monday/current/completed 周，不能信任 server date 或客户端宣称。 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-06-30-01 | T/E | dashboard timezone selection | mitigate | 只读取 records 已确认 preference，ZoneInfo 复验持久值；没有/无效值 fail closed，拒绝 query/header/browser 直传成为权威。 |
| T-06-30-02 | I | timezone/precondition error | mitigate | API 只返回稳定用户修复语义，不回显 DB、provider、stack、用户数据或内部 exception。 |
| T-06-30-03 | T/R | history/weekly cache facts | mitigate | 不改 immutable `consumed_local_date`、HMAC cursor、facts digest、advisory lock 或版本化 cache key；仅修正 current window。 |
| T-06-30-04 | S/E | cross-tenant preference read | mitigate | repository query 固定 `DashboardTimezonePreference.user_id == authenticated user_id`，PostgreSQL test 覆盖 owner/foreign 行。 |
| T-06-30-05 | D | DST/host-TZ boundary behavior | mitigate | injected aware UTC clock + ZoneInfo tests覆盖 Shanghai、Los Angeles、DST 和 Monday；禁止 `date.today()`/进程 TZ 默认值。 |
| T-06-SC | Tampering | npm/pip/cargo installs | accept | 使用 Python 标准库 `zoneinfo` 和现有依赖，不新增或安装包。 |
</threat_model>
