# Phase 6 — UI 设计合同：用户看板与后台管理

> 本文是实现、测试和验收的视觉与交互真相来源。已冻结的 H5 基座、阶段 CONTEXT 和 AI-SPEC 优先于一般设计偏好。

---

## 设计系统

| 属性 | 用户 H5 `frontend/` | 独立后台 `admin-frontend/` |
|---|---|---|
| Tool | shadcn/ui 官方 registry | shadcn/ui 官方 registry；独立 Vite SPA，不导入用户 H5 页面 |
| Preset | `base-nova`、`slate`、CSS variables（`frontend/components.json`） | 复用同一 Base UI、语义 token 和组件约定；独立初始化配置，不复制业务组件 |
| Component library | `@base-ui/react` | `@base-ui/react` |
| Icon library | Lucide | Lucide |
| Font | 已有 `Inter, ui-sans-serif, system-ui, sans-serif`；不额外加载远程字体 | 同一系统无衬线字体；数值使用 `tabular-nums` |
| 视觉气质 | 可信、克制、清爽、生活化；不是医疗机构或健身游戏 | 可信、清晰、紧凑、可审计；不是消费端 H5 的放大版 |

禁止新增第二套 UI 库、品牌色、图表库或第三方 shadcn registry。现有 H5 原语 `Button`、`Card`、`Alert`、`AlertDialog`、`Badge`、`Input`、`Label`、`Separator`、`Skeleton` 必须优先复用；后台需要的 `Table`、`Select`、`Tabs`、`Dialog`、`Tooltip`、`DropdownMenu`、`Sheet` 仅可从 shadcn 官方 Base UI registry 引入，并同时更新 `admin-frontend/` 的目录 README/索引。

## 页面与信息架构

### 用户端：仅升级 `/app/records`

`AppShell`、唯一 `PageScrollArea` 和四项 `BottomNavigation` 保持不变；不得新增“看板”“趋势”或“复盘”Tab，亦不得注册 `/admin` 路由。页面在内容滚动区内按下列顺序渲染，不能把周复盘提前到首屏：

```text
记录（h1，焦点落点）
├─ 今日摄入摘要
│  ├─ 已记录总能量、餐食数
│  └─ 蛋白质 / 脂肪 / 碳水目标状态（仅具备完整资料 + 已完成计划资格时）
├─ 本周趋势
│  └─ 周一至今日的 7 日能量趋势 + 可访问数据表
├─ 历史餐食
│  └─ 按实际用餐本地日期分组的卡片列表 → 既有记录详情
└─ 周复盘
   ├─ 本周或已结束周选择器
   ├─ 周范围、已记录天数和餐数
   ├─ 确定性汇总与可见模式
   └─ 最多 3 条受限普通饮食参考，或安全弃权
```

`/app/records` 的视觉锚点是首张“今日摄入摘要卡”中的**已记录能量与餐食数**：它必须在首屏、先于趋势与周复盘，采用该页最高的信息层级和 `tabular-nums`。趋势是对这两个当日事实的次级解释，周复盘是页面末段的可选补充；两者不得以尺寸、色彩或位置抢占摘要卡的优先级。

- 首页默认周为“本周周一至今天”；过去周仅能选择已经结束的完整周。显示周范围时使用“`9 月 1 日—9 月 7 日`”，不得用“这一周一直”暗示连续或完整记录。
- 按用户实际用餐时间归档，补记必须显示在原用餐日期；不可按创建时间排序或归组。用户本地日/周由后端权威投影决定，前端不以 `new Date()` 聚合无界历史。
- 若缺完整个人资料或没有已完成计划资格，今日卡只显示“已记录摄入”和餐数；不渲染空目标条、比较、百分比或猜测目标。
- 历史区首批为服务端有限投影；“加载更多记录”位于列表末尾，追加时保留已读内容、焦点和滚动位置。没有分页时不显示该按钮。

### 独立后台：桌面优先

后台路由仅在 `admin-frontend/` 内：`/admin/overview`、`/admin/catalog`、`/admin/runs`、`/admin/model-configs`、`/admin/audit`。认证恢复后先请求管理员 probe；每个 API 仍由后端数据库当前角色授权，前端守卫和隐藏导航只是减少误操作，绝不是授权。

| 路由 | 页面目的与必含内容 |
|---|---|
| 概览 | 近 24 小时运行总数、失败率、P50、P95、总估算费用；指标口径显示“终态运行、UTC 起止范围”，链接到已带时间范围的运行审计。 |
| 营养目录 | 版本列表、草稿状态、菜品/别名/每 100g 标准营养/来源/授权状态；详情抽屉显示人类可读字段差异、版本和审计摘要。 |
| 运行审计 | 近 24 小时默认表格；时间、状态、图版本、Provider/模型版本、失败节点、失败码筛选；行详情仅显示工具名、耗时、费用、调用数和安全摘要。 |
| 模型配置 | 当前生效的非密钥配置、历史版本、启停状态、单次和周期费用上限；密钥、端点、Provider body 一律没有字段也没有占位值。 |
| 操作审计 | 不可变时间线/表格：动作、对象、操作者、时间、理由、字段级前后值和关联版本；不显示敏感内容。 |

后台使用左侧持久导航、顶部页标题/会话菜单、主要工作区；`≥1280px` 侧栏 240px、内容最大宽 1440px、页面内边距 32px；`1024–1279px` 侧栏 208px、内边距 24px；`768–1023px` 折叠为可键盘关闭的 Sheet；低于 768px 显示“请在至少 768px 宽的设备上使用管理后台”的受控说明和退出入口，不伪装成可操作的 H5 后台。表格区域可横向滚动，但页面根不能横向溢出，首列和操作列在支持时 sticky。

## 布局、间距与触控

### 间距尺度

| Token | 值 | 用途 |
|---|---:|---|
| xs | 4px | 图标与内联元素间距 |
| sm | 8px | 紧凑控件、表格行内间距 |
| md | 16px | 默认卡片/模块间距 |
| lg | 24px | 后台页面区块、H5 重要分隔 |
| xl | 32px | 后台页面内边距、主要栅格间距 |
| 2xl | 48px | 后台重大区块分隔 |
| 3xl | 64px | 后台空态/页面级留白 |

Phase 6 新增组件（用户端和后台）只能使用本表中的 4px 倍数 token；不定义或复用任意值间距。既有 H5 `AppShell`、`PageScrollArea`、`BottomNavigation` 和页面容器继续按上游 [`h5-foundation.md`](../../docs/ui/h5-foundation.md) 的冻结度量运行；它们是既有壳层，不是本阶段新增组件可选的间距值，也不在本阶段重构。

新增 H5 看板组件在既有单列壳层内排布：卡片内边距使用 16px，模块间距使用 16px，主要区块分隔使用 24px；无重阴影卡片瀑布流。既有底部导航与安全区规则保持不变；Phase 6 新增固定区以 8px 作为基础安全区留白并结合 `env(safe-area-inset-bottom)`。唯一纵向滚动仍是 `PageScrollArea`，禁止图表/历史列表各自再建纵向滚动根。

H5 关键按钮、整张可点击记录卡、图表数据点详情入口的命中区域不小于 44×44px；输入高 44–48px。后台鼠标目标至少 32px，高风险操作、筛选触发器和菜单项至少 36px；触控断点保持 44px。

## 排版

Phase 6 新增组件只使用以下 4 个字号和 2 个字重：13px、16px、20px、28px；400、600。数值用同字重加 `tabular-nums`。H5 基座既有页面 `h1` 的 700 与底部 Tab 的 500 是已验收壳层/导航样式，必须原样保留；它们不属于本阶段新增组件的字重选项，不能扩散到新卡片、图表、表格、表单或后台组件。

| Role | Size | Weight | Line Height | 使用 |
|---|---:|---:|---:|---|
| Display / 后台页标题 | 28px | 600 | 36px / 1.2 | 后台每页唯一 h1 |
| Section | 20px | 600 | 28px / 1.2 | 今日摘要、本周趋势、周复盘、后台主要区块 |
| Card / Body | 16px | 600 / 400 | 24px / 1.5 | 卡片标题、表格主字段、说明正文 |
| Supporting | 13px | 400 | 20px / 1.5 | 日期、覆盖、状态、帮助和审计元数据 |

上游 H5 壳层的 Tab 标签保留其既有字号、行高和 500 字重；这不是本阶段新增组件规则。新增表单输入文字为 16px。标题按 `h1 → h2 → h3` 递进，长标题最多两行；后台表格单元格单行截断时必须提供完整可访问名称/Tooltip，不能把数值、版本或失败码裁掉后无办法读取。

## 色彩与状态

所有值是已存在的 CSS 语义 token，而非新品牌色或业务内硬编码色值。

| Role | Value | Usage |
|---|---|---|
| Dominant（约 60%） | `background` / `foreground`（现有 `--background`、`--foreground`） | H5 页面底、后台工作区、正常正文 |
| Secondary（约 30%） | `card`、`secondary`、`muted`、`border` | H5 卡片/底部导航、后台侧栏、筛选区、表格表头与分隔 |
| Accent（约 10%） | `primary` / `primary-foreground`；焦点使用 `ring` | 仅主 CTA、当前 H5 Tab、选中周/筛选、可点击图表当前点、后台当前导航与确认按钮 |
| Destructive | `destructive` / `destructive-foreground` | 失格、停用 Provider、发布撤销等高风险动作及不可恢复错误 |

Accent 绝不用于普通卡片、每个链接、成功/失败判断或纯装饰。目标状态、运行状态、授权状态必须有文字和图标/Badge，不能只变色；成功/信息状态优先用 `Badge` 的语义文本搭配 `secondary`/`outline`，除非基础 token 已定义其语义色，不新增私有绿色或橙色。现有 `.dark` token 只作预留，本阶段不添加主题切换。

## H5 组件与交互契约

| 组件 | 内容与状态 | 交互/可访问性 |
|---|---|---|
| `TodaySummaryCard` | “今日已记录摄入”、能量、餐食数；这是 `/app/records` 的首屏视觉锚点。有资格时再显示三种宏量的“低于/处于/高于目标区间”。 | 能量与餐食数必须同卡、先于趋势与复盘，并用 `tabular-nums`；数值无小数伪精度。无资格时显示“暂未提供目标对比”，并说明“完成个人资料和饮食计划后可查看”，不显示 CTA 以外的假数值。 |
| `WeeklyTrend` | 标题、周范围、原生 SVG 七点折线、每一天的日期/已记录能量/是否无记录。 | SVG 仅视觉增强；紧随一个始终存在的语义 `table` 或 `details` 数据表。每个点必须有可聚焦 button/链接，名称为“周X，X月X日，已记录 X kcal”或“无已保存记录”；不可只靠 hover Tooltip。无记录点用虚线/空心标记加文本。 |
| `HistorySection` | 实际用餐日期分组、既有记录卡、首批加载与“加载更多”。 | 日期 `h2`，记录为真实 `Link`；追加加载 `aria-live="polite"` 宣布“已加载 N 条记录”，不重置内容区 scrollTop。 |
| `WeeklyReview` | 周选择、覆盖范围、确定性汇总、模式、1–3 条建议及精确免责声明。 | 周选择是有可见 label 的 select；切换后局部 Skeleton、保留旧内容直到新数据成功或显示错误。建议只能使用“根据已记录餐食”“可以考虑”等条件语气；每条 ≤220 字，不显示技术、模型、Provider、token、费用、原始 JSON、思维链。 |
| `ReviewInsufficientCoverage` | 仅用于稳定状态码 `INSUFFICIENT_COVERAGE`：显示周范围、已记录天数/餐数和已有确定性汇总。 | 固定正文：“本周仅记录了 {days} 天、{meals} 餐；现有记录不足以判断趋势或提供饮食参考。”不显示趋势判断、建议、建议占位、生成状态或重试控件；该路径后端不得调用模型。 |
| `ReviewSafetyAbstention` | 仅用于安全弃权（例如 `WEEKLY_REVIEW_SAFETY_REJECTED` 或医疗/限制性饮食高风险触发）：显示周范围、已记录天数/餐数和已有确定性汇总。 | 标题“本周不提供饮食参考”；正文“为避免给出不适合的饮食建议，本周不提供个性化饮食参考。”不显示建议、建议占位或重新生成控件；不得暴露触发规则、模型输出或技术错误。 |
| `ReviewServiceFailure` | 仅用于可重试服务失败（Provider 停用、预算拒绝、超时或 `OUTCOME_UNKNOWN`）：显示周范围、已记录天数/餐数和已有确定性汇总。 | 标题“本周复盘暂时不可用”；正文“已保留本周的记录汇总，请稍后重新生成本周复盘。”不显示建议或技术错误；显示唯一按钮“重新生成本周复盘”。 |

图表不引入 Recharts、Chart.js 或其他未核实依赖。实施采用小型原生 SVG 折线（固定最多七点）+ HTML 数据表；若之后需要缩放、多序列或大数据量，必须先完成依赖审计和单独设计决策。图形有 `role="img"`、简短 `aria-label` 概述，表格是屏幕阅读器和键盘的完整事实源；颜色之外使用线型/空心点表示缺失；`prefers-reduced-motion` 时禁止路径绘制动画。

### 用户端状态与文案

| 状态 | 必须呈现的文案和行为 |
|---|---|
| 首次加载 | 页面标题与四 Tab 可用；今日卡、趋势和历史各用尺寸匹配的 Skeleton，周复盘显示“正在整理已记录餐食…”。禁止整页空白或旋转遮罩。 |
| 无记录 | 标题“还没有已保存的餐食”；正文“完成一餐分析后，确认保存即可在这里查看。”；唯一主 CTA“去分析一餐”。不显示趋势线、周建议或假零值。 |
| 无计划/资料 | 摘要仅显示实际摄入；辅助文案“暂未提供目标对比。”禁止推测个人目标。 |
| 记录请求失败 | `Alert` 标题“暂时无法加载记录”；正文“请检查网络后重新加载记录。”；按钮“重新加载记录”。已成功加载的其他区块保持可读。 |
| 历史为空但今日有记录 | 显示今日组；历史区说明“还没有更早的已保存餐食。”不能把今日误作空态。 |
| `INSUFFICIENT_COVERAGE` | 使用 `ReviewInsufficientCoverage` 固定文案；只显示周范围、覆盖和确定性汇总，禁止趋势判断、建议与重新生成控件，且后端不得调模型。 |
| 安全弃权 | 使用 `ReviewSafetyAbstention` 固定标题与正文；显示周范围、覆盖和确定性汇总，禁止建议与重新生成控件。 |
| 完整复盘 | 覆盖范围始终在建议之前；免责声明精确为“仅基于已记录数据，供一般饮食参考，不构成医疗建议。” |
| 可重试服务失败 | 使用 `ReviewServiceFailure` 固定标题与正文；显示周范围、覆盖、确定性汇总和“重新生成本周复盘”按钮；不把 timeout、预算或 Provider 错误暴露给用户。 |

三个状态必须互斥：同一次周复盘响应只能映射其中之一，不能用覆盖不足文案掩盖安全弃权或服务失败。

| 周复盘状态 | 必须可见 | 建议 / 恢复操作 | 浏览器验收 |
|---|---|---|---|
| `INSUFFICIENT_COVERAGE` | 周范围、已记录天数/餐数、确定性汇总和低覆盖固定正文 | 不显示建议；不显示恢复操作 | 通过真实页面与公开 API 打开低覆盖周，确认不出现建议、生成中或“重新生成本周复盘”。Provider 零调用由自动化契约测试断言，不把内部计数暴露到浏览器。 |
| 安全弃权 | 周范围、已记录天数/餐数、确定性汇总、安全弃权标题和正文 | 不显示建议；不显示恢复操作 | 通过真实页面与公开 API 返回安全弃权，确认不出现建议、恢复操作、触发原因或技术细节。 |
| 可重试服务失败 | 周范围、已记录天数/餐数、确定性汇总、服务失败标题和正文 | 不显示建议；唯一恢复操作为“重新生成本周复盘” | 通过真实页面与公开 API 返回可重试服务失败，确认唯一按钮文字准确、点击后仅重新请求本周复盘，并保留原有汇总。 |

## 后台组件、高风险操作与状态

后台新增组件默认 16px/24px 正文与表格主字段、20px/28px 区块标题、28px/36px 页标题；列表行 44px，信息密度高但每列不拥挤。筛选栏在宽屏单行，窄屏自动换为两列/单列且“应用筛选”“重置筛选”保留可见文本。每个筛选变量写入 TanStack Query key，翻页用后端 opaque cursor；更改筛选时回到首批，不在浏览器端复制/重排全量审计数据。

| 组件 | 必须行为 |
|---|---|
| `AdminDataTable` | 真实 semantic `table`；列标题可排序时是 button 并声明 `aria-sort`；筛选字段有 label；空结果只说明“没有符合当前筛选条件的运行/审计记录”，提供“重置筛选”。加载以表头、列数和行高相同的 Skeleton 表示。 |
| `RunMetrics` | 四张等权指标卡：总运行数、失败率、P50、P95、总估算费用；显示固定“近 24 小时（UTC）”和终态口径。卡不假装精确实时；刷新只局部更新并用 polite live region 宣布。 |
| `RunDetailDrawer` | 抽屉标题为运行 ID 的短形式，包含版本、状态、工具名、耗时、费用、调用数、失败码与安全摘要。绝不请求或展示邮箱、用户原文、图片、完整 State、Provider body、密钥、端点、模型思维链。 |
| `CatalogEditor` | 草稿可编辑的显式字段；每个字段的校验贴近输入；来源链接以安全外链呈现；版本/授权不可被“就地发布”静默覆盖。编辑保存后显示新的 revision。 |
| `FieldDiffPreview` | 两列“当前值 / 拟发布值”，逐字段列出菜名、别名、每 100g 营养、来源、授权状态；变更行带文字“已修改/已新增/已移除”，并显示受影响菜品数量。原始 JSON diff 禁止作为主界面。 |
| `AuditTimeline` | 每项含动作、对象、操作者、时间、理由、字段级前后值、关联版本/命令 ID；理由可折叠但默认可读取，不写入敏感 payload。 |
| `ConfigVersionForm` | 只可填 model alias、费用上限、启停状态及非密钥配置；每次保存均须非空理由。密钥字段、掩码值、复制按钮和“查看密钥”入口都不得出现。 |

### 高风险确认统一流程

下列动作都是不可直接提交的命令：目录审核、发布新版本、立即失格、停用 Provider、启用 Provider、变更模型版本/单次费用上限/周期费用上限。统一采用 `AlertDialog`，焦点初始落在“取消”，Escape 只关闭不执行，确认后禁用重复提交并以 `aria-live="polite"` 报告结果。

1. **预览：** 先由服务器返回字段级差异、影响数量、当前 revision/版本和动作后果；客户端不得自行生成可信 diff。
2. **理由：** 必填、可见 `label`、最少 1 个非空白字符，提交前显示字段级错误“请说明此次变更原因。”；理由和确认结果进入操作审计。
3. **确认：** 对话框标题与动作一致，例如“发布营养目录版本？”；正文精确说明影响，例如“发布后，新分析和新餐单将使用此不可变版本；历史已确认餐食不会被改写。”主按钮使用动词对象（“确认发布版本”“确认立即失格”“确认停用 Provider”），取消始终可用。
4. **完成/冲突：** 成功后关闭对话框、刷新关联列表/详情/操作审计并公告“已发布版本 vX，操作已记录。”；`If-Match` 冲突保持编辑内容与服务器最新 diff，提示“此草稿已被其他管理员更新。请查看最新差异后重新确认。”不得自动覆盖或重试命令。

Provider 停用确认必须额外显示：“将立即阻止新的模型调用；已发出的调用会按原有超时结束并完整记账。”配置更改确认必须显示：“只影响此后启动的运行；正在执行的运行按启动时配置完成。”失格确认必须显示：“仅阻止后续分析和新餐单使用该条目，不重算或删除历史餐食快照。”

### 后台权限、错误与空态

- 登录恢复中：显示受限后台 shell Skeleton，不闪现任何数据或菜单的授权结论。
- `401`：清除内存 access token，跳转后台登录入口，文案“登录已失效，请重新登录。”保留 `returnTo` 仅限后台相对路径。
- `403` 或 probe 非 admin：显示“无后台访问权限”“你的当前账号没有管理权限。请使用管理员账号登录。”，提供“返回用户端”与“重新登录”；不显示 cached admin data，也不反复刷新。
- 普通查询失败：表格/卡片内 `Alert` 提供“重新加载当前管理数据”；不得显示 HTTP 状态、堆栈、原始错误、密钥或 payload。
- 目录/运行/审计筛选无结果：只在表格内容区显示空态和“重置筛选”，不删除筛选栏或导航。
- 无权、加载、空态和错误均不改变 URL 到一个虚假成功页；审计历史不可被客户端编辑/删除。

## 键盘、屏幕阅读器与动效

- H5 保持 AppShell 的“跳到主要内容”链接；页面载入后 `h1` 可程序化获得焦点但不触发滚动重置。后台同样提供 skip link：跳过侧栏至 `main`。
- 所有 icon-only 控件有具体 `aria-label`；导航使用 `nav` + 真 `Link`，当前项以 `aria-current="page"` 传达。禁止 clickable `div`。
- `AlertDialog`、抽屉、Sheet 开启时焦点被正确约束，关闭后回到触发控件；Tab 顺序等于视觉顺序。错误关联 `aria-describedby` 和 `aria-invalid`，动态成功/追加/筛选结果用非侵入 `aria-live="polite"`。
- 正文/背景至少 WCAG AA 4.5:1，大字至少 3:1；不能仅通过颜色、形状或 hover 传递关键信息。后台数据表可用键盘到达筛选、排序、行详情、分页/加载更多与操作菜单。
- 普通 transition 150–200ms，复杂切换不超过 300ms；无大幅缩放、持续漂浮、滚动劫持或强制 scroll-snap。`prefers-reduced-motion` 关闭非必要动画，包括 SVG 路径动画和 Skeleton 强闪烁。

实现完成后必须以真实页面和公开 API 走一次内置浏览器验收；不得写数据库、伪造 token 或调用内部函数替代。

1. 注册、邮件验证、真实登录；保存包含接近午夜与补记日期的餐食；访问 `/app/records`，确认“今日 → 本周 → 历史 → 周复盘”顺序、四 Tab 不变、补记回到实际日期。
2. 覆盖无记录、无计划/资料、记录加载错误、本周、已结束完整周、长历史追加，以及下列三个互斥的周复盘状态。验收须使用产品真实页面与公开 API，分别确认可见内容、无建议/重试规则和精确按钮文案；屏幕上不得出现模型技术细节：
   - `INSUFFICIENT_COVERAGE`：仅见周范围、已记录天数/餐数、确定性汇总和“本周仅记录了 {days} 天、{meals} 餐；现有记录不足以判断趋势或提供饮食参考。”；没有建议、没有“重新生成本周复盘”。Provider 零调用由自动化契约测试断言，不向浏览器暴露内部计数。
   - 安全弃权：仅见周范围、已记录天数/餐数、确定性汇总和“本周不提供饮食参考 / 为避免给出不适合的饮食建议，本周不提供个性化饮食参考。”；没有建议、没有“重新生成本周复盘”，也不显示安全触发原因。
   - 可重试服务失败：仅见周范围、已记录天数/餐数、确定性汇总和“本周复盘暂时不可用 / 已保留本周的记录汇总，请稍后重新生成本周复盘。”；没有建议，唯一恢复操作为“重新生成本周复盘”。
3. 用真实管理员登录独立后台；以普通用户与过期会话各验证一次拒绝体验。创建目录草稿、核对人类可读字段差异与理由、审核、发布、失格；确认历史餐食快照不变。
4. 在后台按过滤条件查看运行；核对 24 小时指标同列表口径，详情只含最小字段；变更非密钥配置，确认新运行使用新快照、已启动运行不被改写，操作审计可见。
