    - Test 1: delete 在 provision intent 被 worker claim 前发生：事务取消 pending intent，worker 不调用 remote create。
    - Test 2: worker claim 后、remote create 前：worker 在每次外呼前以锁重新读取 ledger active/deleted 状态；若已删，取消而不外呼。
    - Test 3: remote create 成功后、local external-ID bind 前 delete：worker re-lock 发现 deleted，写/补全 durable delete intent（ID 或 request key），不重新激活 ledger；最终 remote record 被删除。
  </behavior>
  <action>扩展现有 lifespan memory cleanup callback 为 provider-work callback，仍使用一把 PostgreSQL advisory lease、`FOR UPDATE SKIP LOCKED`、有界 retry/backoff 和安全计数，不新建进程内 background task。唤醒由 capture/delete 触发，但所有实际领取由 worker 完成。

实现精确时序：claim 后提交/释放 claim 事务，外呼前另行 locked active/deleted recheck；外呼成功后再 locked bind。delete 总是在事务内 soft-delete ledger：pending 未 claim intent 标 cancelled；claim/unknown/remote-created 情形保留/创建 delete intent。若外部已创建而本地 bind 时 ledger 已删，记录 external ID 或 stable request key 到 delete intent，安排删除并保持 ledger deleted；绝不能 provisioned/reactivate。Deletion worker 可用 exact key resolve 尚未 bind 的 remote ID 后删除。任何未知 Provider outcome 仍只 resolve，不能再 create。</action>
