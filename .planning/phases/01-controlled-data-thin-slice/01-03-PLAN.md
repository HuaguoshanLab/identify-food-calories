- `GET /api/v1/dishes?query=<1..50>&limit=<1..20>` → `{ items: Array<{ dishId, name, matchedAlias?, typicalServingGrams, dataStatus }> }`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| untrusted browser JSON/query → Pydantic/API | Dish ID, grams, query, limit, and unexpected fields cross from client to API. |
| API router → service/repository → PostgreSQL | HTTP must not gain direct SQL authority; only repository performs data access. |
| PostgreSQL controlled data → API response | Private source/license/version/PK fields must not cross to users. |
| browser origin → API | A locally running browser may make cross-origin REST requests. |
| future image/model/multi-dish input → API | No such endpoint or parser is introduced; this plan actively inventories routes to prevent accidental expansion. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-11 | Tampering | calculation request | mitigate | Pydantic accepts only dishId/Decimal grams, bounds grams, service ignores/rejects client nutrition/model/source fields, and TDD covers each invalid payload. |
| T-01-12 | Injection | search repository | mitigate | Repository owns parameterized SQLAlchemy queries and bounded query/limit; routers cannot execute SQL. API tests use quote-like query input and verify no server error/leak. |
| T-01-13 | Information Disclosure | API errors/DTOs/OpenAPI | mitigate | Separate response schemas and exception envelope whitelist fields; contract tests assert no ORM, DB URL, stack, license, source, or model data appears. |
| T-01-14 | Spoofing / Information Disclosure | CORS | mitigate | Explicit only-localhost origin, explicit methods/headers, `allow_credentials=False`, and preflight tests for allowed and foreign origins; no wildcard. |
| T-01-15 | Tampering | calculation authority | mitigate | Formula exists only in `CalculationService`, uses repository-fetched governed record, and no client kcal field is accepted. |
| T-01-16 | Denial of Service | query/grams endpoint | mitigate | Bound query length/limit and grams; no image decoding/model calls/database scans; Phase 5 owns anonymous rate/cost controls. |
| T-01-17 | Spoofing / Tampering | upload, image, model, multi-dish surface | accept — out of phase | Route inventory and OpenAPI tests require only GET dishes and POST calculations. With no multipart parser/storage/provider route, image and multi-item threats do not yet exist; Phase 2 owns them. |
| T-01-SC | Tampering | package supply chain | mitigate | This plan consumes the Plan 01 lockfile and may not add unapproved packages; keep the package-source gate in the dependency summary. |
</threat_model>
