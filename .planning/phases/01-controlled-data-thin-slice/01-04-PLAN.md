<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user text/form state → typed frontend transport | Alias query and grams can be malformed or stale before entering the API. |
| frontend transport → FastAPI contract | Browser must use only published endpoints and safe errors. |
| backend result → rendered UI | Returned calories are untrusted for display shape but authoritative for calculation; UI must not recompute them. |
| browser test/manual browser → local services | E2E must prove the real API/database path rather than a mocked lookalike. |
| future image/multi-dish input | The page intentionally has no file input, multipart call, image preview, provider integration, or multi-dish state. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-18 | Tampering | browser request construction | mitigate | Typed functions send only documented `dishId`/grams, component validation prevents invalid submits, and API remains final validation authority. |
| T-01-19 | Information Disclosure | error rendering | mitigate | `http.ts` retains only safe envelope fields and UI uses fixed fallback copy; tests reject raw server/stack rendering. |
| T-01-20 | Repudiation / Tampering | displayed kcal | mitigate | UI renders API response only, marks stale results after input change, and tests prove no TypeScript calculation exists or occurs on grams edits. |
| T-01-21 | Denial of Service | repeated submit/search | mitigate | debounce search, disable calculation CTA while pending, and require explicit form submit; Phase 5 owns server-side anonymous rate/cost controls. |
| T-01-22 | Spoofing / Tampering | images, uploads, vision, multi-dish | accept — out of phase | Browser/UI, transport types, E2E route assertions, and docs contain no file input/multipart/model/multi-dish operation. Phase 2 owns their validation, deletion, and model safety. |
| T-01-23 | Information Disclosure | data provenance UI | accept — intentionally withheld by D-06 | API returns `dataStatus` for traceability but UI does not display source/license/provenance in Phase 1; DTO tests prevent accidental internal-field display. |
| T-01-SC | Tampering | package/tool chain | mitigate | Use the Plan 01 approved lockfile and official Base UI primitives only; E2E/tool commands add no new unreviewed package. |
</threat_model>
