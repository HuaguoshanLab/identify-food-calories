<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| versioned manifest → seed command | Repository data becomes database records and must not partially apply or lose provenance. |
| seed/preflight command → PostgreSQL | Scripts use privileged data access and must target the isolated configured database. |
| database → future API | Private license/provenance fields must not become accidental public response fields. |
| future images/multi-dish recognition → catalog | No Phase-1 writer consumes uploaded/model data; only reviewed manifest data can seed the catalog. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-06 | Tampering | catalog manifest/seed | mitigate | Strict manifest validation, stable-ID upsert, one transaction with rollback, and real PostgreSQL malformed-record integration tests. |
| T-01-07 | Tampering / Repudiation | nutrition provenance and release status | mitigate | Persist source, commercial-use/license reference, derivation note, immutable version/status; production preflight checks manifest plus DB and exits non-zero. |
| T-01-08 | Elevation of Privilege | test/seed database access | mitigate | Require `TEST_DATABASE_URL` distinct from development URL; test setup fails closed and scripts use explicit commands, never app startup. |
| T-01-09 | Information Disclosure | catalog internals | mitigate | Models are persistence-only and no endpoint exists in this plan; Plan 03 response schemas whitelist public fields only. |
| T-01-10 | Spoofing / Denial of Service | image, multipart, model, or multi-dish inputs | accept — out of phase | The schema has no analysis/image tables and no HTTP route accepts these values. Phase 2 is responsible for image decoding, size limits, deletion, and model-output validation. |
| T-01-SC | Tampering | dependency supply chain | mitigate | No new packages are installed in this plan; Plan 01's blocking source-verification gate and lockfile remain required. |
</threat_model>
